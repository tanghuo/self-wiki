# 个人 Wiki

本地优先的个人内容空间：图片、视频、文字和会话都是可关联、可打标签的元素。维护路径为 Node/Electron/React。

界面默认采用柔和的暖纸配色，可在“设置 → 外观 → 主题色”切换暖纸、青苔、夜间或浅色。主题立即生效并自动保存，内容和关系画布共用；刷新或重新打开桌面客户端会保留选择。内容分类、关系画布和设置集中在侧栏；窄窗口下自动排列为顶部导航。图片完整展示，加载中显示预览占位，标签浮在卡片左下角。内容默认使用瀑布流，也可切换为网格；瀑布流工具栏的“图片大小”可在 200–560px 之间调节列宽，默认为 320px，窗口不足一列时自动适应。视图和大小会在当前浏览器中记住。

主页和关联内容卡片按实际显示宽度及屏幕像素密度选择 400、800、1200 或 1600px 宽的 WebP 预览。放大卡片或调整窗口时自动选择合适清晰度，竖图按宽度缩放，超长图最高 3200px；小原图不放大生成。预览按需加载，详情和下载继续使用保存的原图。预览持久保存在 `assets/previews-v1/`，重启后复用；永久删除原图时同时清理对应预览，离线文件清理工具也可清除孤立预览。新导入图片记录方向校正后的尺寸并准备 400/800px 预览；旧库启动后按最新内容优先、每批 32 张在后台补齐，失败项下次启动重试。前台预览优先于后台分析，总生成并发最多 2 路、后台最多 1 路。

首页按图片尺寸预留位置，提前请求后续内容；长列表以 36 项为区块，提前约 4000px 挂载，卸载远处卡片并保留滚动占位。图片在进入屏幕前主动加载并解码，预加载最多同时处理 4 张，优先准备离屏幕近的图片；前 8 张直接加载。加载中仍可打开和选择内容，失败可点击“重试预览”重建缓存。内容变化后通过单次范围请求刷新已浏览页，相似堆叠在数据未变化时复用分组结果。视频封面提前 1000px 读取，首次取帧最多同时处理 2 个视频；离开预取区域会取消排队或释放解码资源。

内容库工具栏的“堆叠相似内容”默认开启，可关闭并记住选择。通过双向“相似”直接关联连成一条链的图片和视频只显示一张卡片，封面是最新添加的成员（相同时间取较大的编号），编辑标签不会改变封面。卡片背后的层叠边缘和右上角数量表示整组内容；点击数量打开全部成员，按添加时间从新到旧浏览。搜索、标签或类型筛选时，封面改为组内最新的匹配成员，展开仍显示整组；分组在分页前完成。批量管理和回收站逐项展示。文字、同标签内容、其他关联及尚未建立关联的相似推荐不参与堆叠；删除成员或解除“相似”链路后，分组随之更新。堆叠不合并或删除原内容。

右键内容卡片或详情页原图可“加入参考”，最多收集 12 份，重复添加不会重复收录。参考列表、顺序和折叠状态会在当前浏览器或桌面客户端中保存，刷新或重启后自动恢复，桌面启动端口变化也不影响。移除、清空或进入对话后的列表变化同样会保存；恢复时跳过已删除内容，暂时读取失败的参考会保留并提供重试。

## 保存与关联内容

图片、视频和文字都可以标记为素材：右键卡片选择“设为素材”，详情页切换“用作素材”，也可在批量管理中统一设置或取消。卡片显示“素材”标识；列表上方“仅看素材”可与内容类型、标签和搜索组合，选择会在切换分类及刷新后保留。素材标记不复制或移动内容，不改变添加来源、标签和关联；“加入参考”仍仅表示本次使用。新增内容时可勾选“本次内容用作素材”，相同图片或视频复用已有元素时也会补上标记，普通导入不会取消已有标记。

右键文字卡片选择“编辑文字”，或在详情正文旁点击“编辑文字”，可以修改正文和标签。保存后列表、详情与搜索同步更新，关联保留；保存失败时草稿保留，可重试。关闭有修改的编辑窗口时会提醒确认，避免误丢未保存的内容。

在内容库与 Wiki Agent 之间切换，会保留本次打开的搜索、筛选、详情阅读位置及画布视野。手机导航将整理历史、用量和设置收进“更多工具”。新增内容和设置窗口有未保存修改时，关闭会先询问是否放弃；回收站图片提供缩略图、原文件名和删除时间，便于恢复。修复范围及验证记录见 [UI 与业务一致性修复](docs/ui-review-fixes.md)。

内容详情记录添加方式：直接输入、粘贴或导入为“手动添加”，通过会话保存为“会话保存”。API 字段为 `creationSource`（`manual / chat / unknown`），图片去重后保留首次记录的添加方式。历史内容没有可靠记录时显示“添加来源未记录”；会话复用过图片不代表该图片最初由会话创建。参考关系两端分别显示“参考了”和“被参考”，详情中的“被参考”分组列出使用当前内容的结果，与该内容自身的创作来源分开。

Agent 生成的图片在图内左下角提供“编辑”，点击直接进入修改输入框；点击图片本身打开预览，右下角下载原图。图下的图标可以复制原图或“保存至 Wiki”，悬停会显示操作名称，复制与保存会显示结果。文字回答也可原样或编辑后保存。图片通过普通关联连接会话、参考资料和编辑原图，保存后自动提炼一份可独立执行的提示词，并作为关联文字保存。提示词展开最终采用的人物、服装、场景和光线等特征；来源放在关联中，正文不依赖“图 1”或旧会话。提炼失败可重试，已保存图片仍保留。

会话不出现在“全部内容”，可从 Agent 会话列表或其他元素的关联进入详情，查看附近的对话摘录，再点击“打开会话”跳到原位置。标签与关联沿用普通元素操作。执行、生成、提取等操作仅为底层记录，不创建元素。“提取元素建议”仍可手动寻找完整提示词、方案或结论，最多提出 3 个候选供采纳，零碎修改留在会话。会话和自动保留的中间图片仅供本机浏览；主动保存的结果沿用普通共享范围。详细边界见 [元素生命周期设计](docs/element-lifecycle-design.md)。

应用默认进入“Wiki Agent”，从侧栏“全部内容”进入内容库，点击右上角“新增内容”，在同一个输入区连续加入图片和文字。直接输入一段文字，点击“添加文字”再写另一段；图片可以粘贴、拖入或通过“导入图片”选择文件，加入后显示预览。也可在内容页面直接粘贴或拖入图片打开该窗口。点击“保存全部”后，每张图片、每段文字各自成为一个独立元素；空白文字框会跳过。

混合保存逐项显示进度。部分失败时，成功项显示“已保存”，失败草稿保留在窗口中，可修改或移除后“重试未保存项”；重试跳过本次已确认保存成功的项。已有成功项时，本次公共标签固定，未保存项仍可单独补标签。保存过程中暂时禁止关闭和切换工作空间。一起输入不自动建立关系；打开任意内容，点击“添加关联”选择已有内容，或者新建文字并关联。

图片和文字使用同一套标签。“本次标签”会同时添加到本次所有图片和文字；展开某一项的“单独加标签”，可以补充仅属于它的标签。输入文字后按回车，会在同一个输入框内生成带底色的标签块，光标留在后面继续输入；点击标签上的 × 可移除。也支持用逗号分隔多个标签，直接保存会收下尚未按回车的输入。每个元素合计最多 30 个标签，每个最多 60 字，忽略大小写与首尾空白去重。列表的“全部标签”下拉框可按标签筛选，并与关键词、内容类型组合使用。

“设置 → 名称与别名”可分别管理标签和关联名称：填写别名与主名称，预览使用数及内容例子后应用。内置 `prompt / prompts → 提示词` 标签规则；其他同义叫法可自行归并。已有标签、筛选结果、标签集合和画布按主名称汇总，输入或搜索别名仍可找到内容，AI 和手动新增也会复用已确认的规则。有向关联须同时填写正反名称，保持两端方向；未知方向和旧标题关联不参与归并，“提示词匹配”与“生成自”不会自动互相归并。

别名支持串联，禁止循环。原始绑定和 AI 来源记录会保留，解除规则后可恢复未另行编辑或删除的旧叫法。完全等价的历史关联折叠为一条，显式改名或删除这条关联会作用于整组。第一版不自动判断陌生词是否同义，也不增加上下级体系；新词沿用现有自动整理/建议采纳策略。实现与验证边界见 [名称归一设计](docs/vocabulary-design.md)。

关联支持“相关、相似、提示词匹配”的双向同名关系，以及“参考了/被参考、改写自/被改写为、生成自/生成了、包含/属于”的有向关系。添加或点击关联名称编辑时可选择预设、自定义正反名称及交换方向，并预览两端的读法。双向同名可留空为普通关联；有向关系需填写两端名称。详情和画布会按方向显示，画布箭头指示正向名称的方向，批量重命名保留各条方向与反向名称。旧方向性名称标为“方向待确认”，不按编号猜测；旧标题关系保留专有方向。同一对内容可保存不同名称的关联，同名但方向不同需编辑现有关联。AI 标记、依据与撤销机制独立保留，人工修改方向后不会被 AI 撤销删除。新增和编辑内容只有文字输入和标签，不设标题字段。

“设置 → 浏览偏好 → 标签显示”可选择“始终显示”（默认）或“鼠标悬浮时显示”，用于图片和文字卡片上的标签，网格与瀑布流均生效。修改后立即生效，并在当前浏览器或桌面客户端中自动保存。悬浮模式下，键盘聚焦卡片也会显示标签；触屏设备始终显示。

已有关系可在详情页直接点击关联名称修改后保存；鼠标悬停或键盘聚焦时显示铅笔提示，触屏保留小图标。留空恢复默认名称。重命名保留原关联，双方详情和画布同步显示新名称。同一对内容的同类关系如已有该名称，会提示换一个名称。标签关联在来源内容的标签卡片上重命名，对该标签下的全部成员生效。

文字详情的“复制文字”位于正文卡片右上角，点击即可复制完整正文；文字不再显示下载入口。

直接关联 tag 时，详情页显示一张标签集合卡片，包含关系说明、成员数量和最多四份预览（优先图片），点击“查看全部”分页浏览成员。成员不包含当前内容和回收站内容，后续加入或移出标签会自动更新；空标签仍保留关联卡片。每条标签关联在关联区计为一项。通过 tag 反向关联过来的来源仍显示为内容卡片，并标注“通过 #标签 关联”。解除标签关联不会删除标签或成员。

重复图片按原始文件内容判断：完全相同的图片会复用已有元素并补充本次标签，保留原图和关联；改文件名也不会产生新记录。同名但内容不同会分别保留，导入结果提示“同名不同内容，已另存”。如果相同图片在回收站，会提示先恢复。升级前已保存的重复记录不会自动归并，之后导入复用其中最早的在用元素。图片经过重新编码或修改元数据后，文件内容不同，会视为新图片。

支持文字与图片文件名搜索、类型筛选、分页、编辑、复制文字、保存原图、解除关联、回收和恢复。普通关联无向，标题关系有方向，二者可以并存；同一人物可以先用一个文字元素组织多张图片。解除关联不会删除内容。回收站保留文件及原有关联，可在“更多操作 → 批量管理”中删除选中项，或点击“清空回收站”删除所有分页、筛选外的回收站内容。永久删除需确认，会删除原图及相关关联、标签绑定和画布位置，无法恢复。部分失败会提示并可重试；若提示原图清理失败，记录已删除，可关闭应用后使用下文的离线文件清理工具释放遗留文件空间。

日常浏览时卡片只展示内容。需要清理时，打开列表工具栏的“更多操作（…）→ 批量管理”，勾选图片或文字，或全选当前页，再点击“移入回收站”。切换筛选或翻页会清空选择；退出管理后隐藏勾选框和批量操作栏。底部提示可撤销本次删除，也可稍后从回收站恢复。部分删除失败时，成功项可撤销，失败项保留选中并显示原因。详情页也可以单独移入回收站。

图片支持 PNG、JPEG、WebP、GIF，单文件最多 25 MiB，解码总像素最多 4000 万、动画最多 200 帧。导入复制并保存原始字节与嵌入元数据，后续移动来源文件不会影响 Wiki。文字最多 12000 字，保留换行和空格。默认搜索正文、文件名与标签；可选的画面分析和语义检索见后文。

视频支持 MP4（含 M4V）、WebM、MOV，单文件最多 1 GiB。在“新增内容 → 导入图片或视频”选择文件，或直接拖入内容页面，与文字和图片一起逐项保存。视频原文件复制到数据目录的 `assets/videos/`，不依赖来源路径；上传与播放使用流式读写，详情页支持播放、拖动进度和下载原文件。列表与画布用视频图标和文件名展示，打开预览后才加载视频。

视频可以按文件名、标签搜索，通过“视频”分类筛选，编辑标签、添加关联、移入回收站及恢复。完全相同的文件复用已有视频并合并标签，同名不同内容分别保存；回收站中的重复视频需先恢复。永久删除会清理原视频，离线文件检查工具也支持视频缺失和孤立文件检查。备份时需包含数据库和整个 `assets/` 目录。

视频详情中的“时间点与片段”支持手动标注。播放到需要的位置，点击“标记当前时间”，填写说明、片段标签和关联内容；结束时间留空表示时间点，填写后表示时间范围。时间支持秒、分:秒、时:分:秒，精确到毫秒；点击标注可定位播放，播放到片段末尾自动暂停。关联内容的详情页会显示“关联的视频片段”，可直接返回对应位置。

片段标签复用现有标签和别名词表，在内容库搜索标签或标注说明可找到所属视频。整段视频的标签、普通关联以及画布分组保持各自范围，片段标签与关联显示在对应标注下。每个视频最多 500 条标注，每条最多 2000 字、30 个标签及 12 份关联内容。编辑失败会保留草稿，并发修改会提示冲突。标注不复制或裁剪原文件；视频移入回收站后保留标注，恢复时一起恢复，永久删除视频时一并清理。关联目标移入回收站后暂不可打开，永久删除目标时只移除对应片段关联。

导入会检查容器结构和视频轨道，不转码。播放取决于浏览器支持的编码；遇到不支持的编码时可下载后用本地播放器打开。视频分析可按下节启用；视频暂不作为聊天 Agent 参考，不提取字幕。升级会自动迁移数据库并保留原有内容、标签和关联。

### 视频自动标注与相似素材

在设置的“视频分析”中填写 FFmpeg、ffprobe 的可执行文件路径，点击检测；画面分析复用自动整理中配置的 Codex 视觉执行器。视频详情可手动开始、继续、重跑或取消分析；开启自动分析后，后台处理库中尚未分析的视频，包括已有视频。原视频保存和播放不等待分析完成。

分析在本机检测镜头变化、定时抽帧，再把有限帧交给所配置的模型。**本机 Codex 进程不等于离线推理，帧会发送给其配置的模型服务。** 每帧时间对应播放器位置；范围标注来自抽样证据，显示近似时间。达到帧数、处理批次或资源预算会显示部分完成，可继续。

“建议”模式先展示 AI 标签，接受后成为可编辑的时间标注；“自动”模式自动应用。人工修改、拒绝或删除会屏蔽旧 AI 说明及检索证据，重跑保留人工决定。已应用片段标签参与内容库搜索；建议与人工片段说明也可在“相似素材”中按文字查找。开启现有文本语义索引后，片段说明会建立独立的文本向量。

图片与视频详情新增“相似素材”。可用图片、视频代表帧、指定片段或文字查询，点击视频命中跳到对应时间。“不再推荐”按素材配对保存；相似度不自动创建来源关系。视觉检索需要启动可选的本地 SigLIP2 编码服务，再在视频分析设置中启用视觉索引：

```powershell
python -m venv .venv-visual
.venv-visual\Scripts\python -m pip install -r tools/visual-encoder/requirements.txt
.venv-visual\Scripts\python tools/visual-encoder/server.py --download --warmup
```

首次命令会下载模型权重；之后可去掉 `--download`，只使用本机缓存。CPU 为默认设备，有可用 CUDA 环境时可加 `--device cuda`。设置默认服务地址为 `http://127.0.0.1:8767`，模型与修订版本必须和服务一致。该服务独立运行，Wiki 不自动安装 Python、下载权重或启动它；缺少服务时会显示诊断，视频及时间标注仍可使用。Windows 安装包包含服务脚本和依赖清单，Python 与 FFmpeg 需单独配置。

分析配置保存在数据目录的 `video-analysis.json`，示例见 `config/video-analysis.example.json`。派生帧保存在 `video-analysis-cache/`，不成为图库元素。完整保留分析历史和预览的备份需包含此目录及数据库；永久删除视频后会后台清理失去引用的派生缓存。模型空间隔离，不混用视觉与文本向量。实现与真实模型质量的验证边界见 `docs/video-auto-annotation-design.md`。

已有 Wiki 数据在启动时自动升级：同时有标题和正文的旧记录会拆成两份文字并添加标题关系，只有标题的记录成为一份文字。图片自定义标题迁为关联文字，默认文件名保留为文件信息；原元素编号、标签、关联、原图和画布位置保留。

## 关系画布

在“内容”侧栏选择“关系画布”，以卡片和连线浏览图片、文字及关联。拖动背景平移，滚轮或双指缩放，使用“适应画面”查看当前展开的内容。单击卡片选中并显示右侧预览，双击卡片或点击预览中的“打开详情页”进入完整详情，返回后保留画布视野和筛选。右侧可编辑文字或标签、新增关联、移入回收站及撤销删除；拖动卡片两侧的连接点，填写关系名称后保存关联，点击连线可解除关联。连线显示填写的关系名称；旧标题关系保留方向箭头。

画布提供“关系视图”“平铺视图”和“标签视图”，记住当前设备选择的视图。默认关系视图按连接整理内容，将连接较多的内容放在一侧；连接对象、关系名称相同的四张及以上图片自动收成可展开的图片组。分组只整理当前已加载内容，不合并元素、不推断生成顺序，也不改写已保存的位置。点击图片组展开，点击卡片突出直接关联，背景点击恢复总览；“全部连线”可显示所有关系名称。长 UUID 图片文件名在卡片中简化为标签与编号，详情保留原文件名。

标签总览将有标签的内容收进文件夹式卡片，显示整个筛选范围内的元素数量和最多三份内容预览，无标签内容直接平铺。点击标签进入分组，点击“标签总览”返回；多标签元素会出现在每个对应分组中，编辑的始终是同一份内容。分组内可查看和修改关联，总览中的无标签元素也可直接编辑；从总览展开关联会进入平铺视图。

标签视图自动排布，不改动平铺布局。在平铺视图中拖动卡片顶栏摆放，松开后自动保存该元素的位置；“保存布局”保存所有已展开元素的位置。位置保存在数据库中，供本机和局域网共用。保存失败会保留当前摆放，可重试保存或放弃布局更改；布局保存前暂时锁定导航，避免误丢更改。

首次加载 100 张卡片，可通过“加载更多”或详情中的“展开关联”继续加入，最多同时展开 300 张卡片、1200 条连线；标签总览按标签卡片与无标签元素合计计算上限，分组内的内容按需读取，超过时明确提示，其余数据仍然保留。搜索文字或文件名、按标签筛选可缩小范围；展开关联会加入筛选范围外的直接关联。图片使用最大 400×280 像素的静态 WebP 预览，点开或下载才读取原图。画布按需加载，普通列表无需加载画布组件。局域网画布与本机一样支持编辑关联和保存布局。

## 从源码运行

需要 Node.js 24 或更新版本。双击 `run.bat`：安装缺失依赖、构建界面并启动桌面程序。

也可以手动运行：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd run desktop
```

桌面窗口启动自己的后端进程，使用系统分配的本地端口，并从后端同源加载界面。退出时先停止任务、等待清理，再关闭数据库和进程。

仅使用浏览器时：

```powershell
npm.cmd start
```

该命令默认使用 `http://127.0.0.1:8765`。

## CLI 与 agent 操作

启动或重启桌面程序后，可通过 CLI 自动发现本机后端，搜索和读取内容、管理文字/图片/关联、操作回收站。默认输出 JSON，支持 UTF-8 文件和 stdin 输入；`schema` 提供离线机器可读的命令说明。

```powershell

node src/cli/main.js status
node src/cli/main.js elements list --q "资料" --page-size 10
node src/cli/main.js read 123
node src/cli/main.js elements create --body "一份笔记" --tag "资料"
```

## Wiki 对话

对话输入框支持直接粘贴图片。只有图片时也可点击发送或按回车发送，无需填写文字；粘贴图片和所选 Wiki 图片均支持。粘贴图片只保存为聊天附件，发送时交给模型，不自动导入 Wiki，也不触发标签、检索索引或自动整理。未发送附件可移除；已发送附件随会话保留，编辑消息和创建分支会保留相应图片。每张图片最大 25 MiB，粘贴图片和所选 Wiki 资料合计最多 12 份；每轮所有来源合计最多 8 张图片，图片编辑的原图及选区示意图也计入。

新会话的文字、资料、图片及模型选项，以及已有会话的文字和图片草稿，保存在本地资料库中，桌面启动端口变化后仍可恢复。首次发送才创建会话；保存失败会提示并保留输入，可重试。旧版浏览器草稿会在原地址仍可读取时迁入资料库。

“Wiki Agent”是默认首页和独立主入口，提供完整对话区、会话记录，以及查找资料、整理知识和生成内容的起点。可以直接提问，也可先选择 Wiki 中的文字或图片，搜索资料支持关键词和标签。回答逐步显示；主页面点击引用会预览原内容，继续对话或选择“在内容库打开”。

普通对话只向 Codex 提供用户请求和所选材料的正文或图片，以及附件顺序和文件名。Wiki 的标签、关系、管理记录和建议状态不随材料自动进入创作请求；管理规则在调用 `wiki_cli schema` 时提供，提取/归档提示词和自动整理任务使用各自的管理说明。旧会话首次继续时会用正文和图片重建模型上下文，此后正常续接；原有消息、管理数据和调用记录继续保留。

输入框旁可选择模型和思考等级，主工作区和侧栏均可操作；模型列表从当前 Codex 获取，支持刷新。选择会按会话保存，从下一条消息生效；最近一次成功保存的模型与等级也会成为以后新会话的初始选择，重启后仍保留。已有会话保持自己的设置，打开或继续旧会话不会覆盖新会话偏好，分支沿用来源会话。选择“默认”或恢复默认等级也会被记住；空值跟随本机 Codex 默认配置，不影响自动整理。生成中暂时不能切换，保存失败可重试。回答旁会记录本轮请求的模型。

浏览内容库或关系画布时，点击“问 Agent”才打开侧边对话，在详情页可“加入当前内容”。侧边对话可展开为 Agent 主工作区，当前会话、已选资料和未发送草稿会保留；切换页面会收起侧栏，关闭面板不会中断生成。点击“停止”结束当前生成。入口地址分别为 `#agent` 和 `#wiki`；空地址进入 Agent，局域网访问使用相同的入口和功能。

会话使用 assistant-ui 界面、本机 `codex app-server` 和现有 Wiki CLI。默认使用 `codex` 自动查找 PATH；Windows 还会查找 npm 用户安装、常见桌面安装目录及应用旁的 Codex 便携安装（同目录优先较新版本）。可直接在会话点击“检测连接”；仅在未找到程序或需要覆盖默认值时，前往“设置 → Agent 与检索”配置程序绝对路径、数据目录或模型。手动指定的路径找不到时会报错，不会改用其他安装。会话无需开启“导入后自动整理”，也无需配置 MCP。应用不内置 Codex；需使用支持 app-server 客户端工具的版本，当前验证版本为 0.153.1。

助手可以检索已有资料、总结或生成新文字、建议添加标签和关联。所有建议先显示在会话中，新文字可编辑正文和标签后“采纳并保存”，会附上参考来源关联。普通回答也可点击“保存为 Wiki 内容”。已采纳建议可以撤销；如果相关内容已有后续修改，会提示冲突并保留当前数据。首版不覆盖已有正文。

支持多会话并发生成，同一会话同一时刻只生成一轮；停止或失败仅影响对应会话。每轮最多选择 12 份资料、读取 40 份内容和 8 张图片。语义检索沿用现有配置；未启用时仍可用关键词检索。Wiki 消息、已读资料快照和建议保存在本机数据库，删除 Wiki 条目不会清除聊天历史；首版暂无会话删除入口。Codex 数据目录留空时，默认使用当前 Wiki 数据目录下的 `wiki-codex`，聊天和自动整理的会话数据独立保存，同时复用本机 Codex 配置。手动填写绝对路径仍会覆盖默认值。

默认 ChatGPT 登录从运行环境的 `CODEX_HOME`（未设置时为用户目录下 `.codex`）读取当前访问令牌，通过 [Codex app-server 外部认证](https://learn.chatgpt.com/docs/app-server#3c-log-in-with-externally-managed-chatgpt-tokens-chatgptauthtokens)传入进程内存；Wiki 不复制、使用或刷新桌面的刷新令牌，旧的同账号登录副本不再参与认证。运行中的会话在认证重试时重新读取来源令牌；同一已被拒绝的令牌不会反复提交。登录过期、来源退出或认证被拒绝时，自动整理和待生成的图片描述保留在队列中，不消耗失败重试次数，每 10 秒检查恢复后继续。文本和已有描述的索引不受影响。桌面负责续期；桌面长期未运行导致登录过期时，需先在本机 Codex 恢复登录。不同账号的旧独立登录不覆盖，须显式指定其目录使用；手动指定目录使用自己的登录。API key 的初次缓存复用保持原有行为。

配置在每次启动 Codex 进程时从同一来源的 `config.toml` 刷新到 Wiki 管理的运行副本：只需修改原文件，点击“检测连接”后生效，正在生成的会话会在下一轮加载新配置；自动整理在下一次执行时读取更新。原文件和原会话均不修改；来源配置被删除时会清理运行副本，不继续使用旧值。代理、模型服务等设置沿用来源，Wiki 仍显式限制后台整理的 Shell、插件、MCP 等工具能力。默认目录若已有非 Wiki 管理的配置会提示冲突，不覆盖；手动指定目录使用自己的配置与登录。若本机未登录、仅使用系统凭据库或缓存已失效，仍需登录；已出现在桌面端的旧任务不会自动归档。Codex 的上下文记录保存在其数据目录；迁移或清空 Codex 目录后，已有聊天仍可查看，但可能需要新建会话。局域网共享开放相同的会话功能。

会话内置 `list_files`、`read_file`、`search_files` 三个只读文件工具，分别用于列出文件、分段读取文本和搜索文件内容，由应用直接执行，无需额外安装 `rg`。工具访问当前会话的工作目录，支持中文路径和文件名筛选；调用参数、结果和错误可在工具记录中查看。更新后重启应用，旧会话下次发送时也会自动启用。

默认目录直接使用本机 Codex 登录：需要时在 Codex 桌面恢复登录，或在 PowerShell 运行 `codex login`。仅在设置中手动指定独立目录时，使用下面的命令，将路径替换为该目录；如果 `codex` 不在 PATH 中，将第二行换成 `& "Codex 程序绝对路径" login`。

```powershell
$env:CODEX_HOME = "D:\Tools\self-wiki\data\wiki-codex"
codex login
```

登录后关闭此终端，在 Wiki 点击“检测连接”。此环境变量仅作用于该终端，不修改系统环境变量。

选中或经工具读取的内容会发送到所配置的模型服务；使用本机 CLI 不代表离线推理。接入细节、验证范围见 [会话实施记录](docs/wiki-chat-design.md)。

## Agent 自动整理

图片、文字和视频详情的内容信息旁提供“整理记录”弹窗，可手动整理、查看依据和修正结果；视频整理使用首帧匹配相似素材。点击标签或关联旁的 `AI` 标记直接展开对应记录。全库记录从侧栏“整理历史”进入，先显示内容预览和变更摘要，展开后查看依据、确认建议、撤销或打开原内容；点击“批量修正”后才显示多选和替换操作。设置页提供配置、执行器检测和已有文字批量检查入口。

第一版支持导入后后台整理、查找已有内容、生成标签和直接关联建议，并保留依据、拒绝记录和条件撤销。默认执行器为本机 Codex CLI，执行器通过 `probe/execute` 接口接入。需要 Node 24+ 和已安装、可登录且支持图片与结构化输出的 Codex CLI；应用不内置 Codex 二进制。

在“设置 → Agent 自动整理”填写程序路径（默认从 PATH 找 `codex`）、可选的 Codex 数据目录/模型及超时，保存后点击“检测并启动执行器”。如提示需要登录，请在相同数据目录下登录 Codex CLI 后重新检测。CLI 进程在本机运行，内容会交给它配置的模型服务；不等于离线推理。

默认自动整理关闭、处理方式为“先生成建议”。打开“导入后自动整理”后，新建文字、修改正文、导入图片和视频会入队；只改标签或 agent 自己添加结果不会循环触发。未整理过的已有公开视频会补入队列，重启不会重复排入已完成或失败的任务。已有内容可在详情页点击“整理此内容”手动处理，自动开关关闭时仍可使用。退出应用会停止 worker，重新打开继续可执行的未完成任务；检测失败和执行失败均可查看。

“自动添加，可事后修正”会静默添加通过输入校验的标签、图片识别标签和推断关联。标签和直接关联显示小 `AI` 标记，点击可查看来源整理记录及依据。在详情页的“整理记录”或侧栏“整理历史”中，可按次撤销、跨记录多选移除、统一替换标签或关联名称，并翻看历史记录。修正只作用于所选绑定，不会全局重命名标签；已经人工修改或移除的结果不会被批量覆盖，撤销会跳过它们。明确移除或替换的原结果不会被后续整理自动加回。旧记录缺少逐项来源，保留原有的保守整次撤销方式，不追溯标记现有内容。每次最多查看 40 个候选内容、8 张图片、3 轮检索，结果不是全库穷尽判断。

图片与提示词在至少三个独立具体维度高度吻合、包含有区分度的细节组合且没有关键矛盾或候选歧义时，整理器可添加“提示词匹配”关联。该标准由模型判断，并非经过校准的匹配分数；依据记录具体吻合点并注明推断，AI 标记不代表已核实实际生成来源。仅同角色、同标签或同风格不够，未实际查看的图片不做此类匹配。

图片导入后，整理器会主动比较主图与候选图片。实际查看双方画面，判断为同图变体，或主体外观、姿势、构图及有区分度的细节高度吻合时，添加双向“相似”关联，在详情的“可能相关”中展示，并记录具体相似点与差异。仅同角色、同题材或同画风不够；不把全部图片塞进一个“相似”标签，不根据画面相似推断来源。沿用“先生成建议／自动添加”模式与纠正、撤销机制。

文字整理会用正文重合和已启用的语义检索寻找候选，最多提供 8 份候选文字的完整正文供模型核对。核心内容与关键要求一致、仅少量修改或等义改写时建立双向“相似”关联，记录引用与差异；仅主题相同、局部重合或关键要求相反不应关联。设置 → Agent 与检索 → “检查已有文字相似关系”可分批安排已有非私有文字，沿用已保存的“先生成建议／自动添加”模式，也会整理标签及其他关联。开启自动整理后，新建和修改文字自动检查；正文变化会使未经人工修改的旧 AI 文字相似关联失效，等待重新判断，人工关系与使用记录保留。文字页支持相似堆叠，组内最常用的匹配文字作为封面，展开按使用次数（引用 + 复制）排列；按使用次数排序时，以组内最高次数排序，不合并各条计数。局域网不使用本机使用次数。候选有限，判断质量依赖模型，不保证找出所有近似文字。

视频也参与上述相似整理：本机 FFmpeg 提取第一张视频帧，模型实际比较图片与首帧、或两段视频的首帧后，可建立双向“相似”关联。开启“堆叠相似内容”后，同一链路显示最新素材，其余成员放入堆叠。首帧相似不代表整段视频相同，不据此添加整段视频标签或生成来源关系。无需开启整段视频分析，共用“视频与画面检索”中的 FFmpeg 路径；首帧解码失败时可在整理记录查看原因，修复依赖后重新整理。原视频导入与播放不等待整理。

开启“视频分析 → 图片与视频帧视觉索引”后，自动整理用主图片或视频首帧从已索引素材中召回候选；视频候选始终重新核对首帧，不能用命中的中间帧替代。视觉服务未开启或暂不可用时，沿用描述语义、关键词、标签和最近图片／视频候选；视频首轮描述可用于下一轮语义检索。尚未建立帧索引的旧视频主要依靠近期、标签及关键词候选，可能漏匹配。有候选画面时，主图即使已有描述，也会与每轮最多 3 张新候选一起看图，整次仍最多 8 张（含视频首帧）；其他整理按需补看图片。检索没有带来新资料时停止重复分析。真实相似度判断依赖所配置的视觉模型，不保证穷尽全库。实现与历史用量记录见 [用量优化记录](docs/token-efficiency.md)。

图片详情页的原图下方有“图片说明”：可点“修改说明”直接编辑保存，或点“重新识别”让当前模型重新看图。重新识别成功后才替换旧说明，失败保留原文；处理中再次点击不会重复调用。保存说明会更新搜索数据；处理中手动保存的修改优先，迟到的模型结果不会覆盖它。识别操作可以离开页面继续，返回后可查看进度；退出应用会取消未完成的识别并保留旧说明。这两个操作无需额外开启开关。

新生成和重新识别的图片说明会要求模型细致描述主体外观、服饰与配件、姿态和互动、空间关系、背景、构图、光影色彩、表现风格及可辨认文字，优先保留有区分度的细节。通常要求 600–1200 字，复杂画面可写到 1800 字，上限 2000 字；简单图片按实际信息量缩短，看不清的内容不补造。已有说明沿用缓存，需要更新时在图片详情页点击“重新识别”。

详情页可查看整理结果和依据；“撤销本次整理”仅删除这次实际新增的标签/关系，并记住否定结果。第一版使用保守的全库版本检查：分析或整理完成后，只要库中内容、标签或关系有其他修改，旧结果提交/接受/撤销就会报冲突，保留当前数据。此时可重新整理或手动编辑。拒绝记录持续生效，暂不提供解除抑制入口。

配置保存到实际数据目录的 `organization.json`，示例见 [organization.example.json](config/organization.example.json)。`enabled` 控制自动整理，`applyMode` 是 `suggest` 或 `auto`；`executor.type` 首版只支持 `codex-cli`，`executor.codexCli` 可配置 `executable`、`codexHome`、`model`，`executor.timeoutMs` 仅限制后台自动整理任务的模型总时长。聊天、生图及会话内提示词提炼没有整轮时限；连续 3 分钟未收到新进展时只提示等待，有新进展即清除提示，用户可手动停止。配置文件缺失使用默认值，错误配置停用整理器并显示原因，内容库仍可使用。界面保存立即生效；离线改文件需重启。不保存凭据，不自动修改用户的 Codex 配置。更多设计与实现边界见 [实施记录](docs/agent-organization-design.md)。

## 内置语义检索

“设置 → Agent 自动整理 → 语义检索”可独立启用向量索引。应用内置 SQLite + sqlite-vec 0.1.9，向量、分段和图片描述保存在现有 `library.sqlite3` 中；无需部署向量数据库。第一版使用精确余弦检索，组合关键词、标签和最近内容为整理器提供候选。本机内容列表搜索合并正文、文件名、已有图片描述的字面命中与过滤后的语义候选，字面命中优先，其余按语义相关度排序，并保留标签、类型筛选及分页。输入停顿 350 毫秒后查询；向量查询超过 5 秒或服务不可用时回退正文、文件名和已有图片描述的字面搜索并提示。首页语义相似度低于 0.48 的候选不补入结果；此阈值按当前模型的小样本校准，存在泛词漏召回，见 [搜索相关性](docs/search-relevance.md)。语义候选数量沿用设置中的 topK，不保证覆盖所有相关内容；回收站列表仍使用关键词；局域网列表使用与本机相同的搜索。语义查询也可在设置页试用或通过 CLI 调用。

默认配置连接本机 Ollama：`http://127.0.0.1:11434/v1`，模型 `qwen3-embedding:0.6b`，维数 `1024`。需先安装/启动 Ollama 并准备模型，应用不会自动安装模型服务或下载权重：

```powershell
ollama pull qwen3-embedding:0.6b
```

若 Ollama 尚未运行，运行 `ollama serve`，然后在设置中启用语义索引、保存并“检测向量服务”。Ollama 提供兼容的 `/v1/embeddings` 接口；qwen3-embedding:0.6b 的输出维数为 1024。[Ollama 接口文档](https://docs.ollama.com/api/openai-compatibility)、[模型规格](https://ollama.com/library/qwen3-embedding:0.6b)。也可配置其他兼容服务，地址填到 `/v1` 等接口根路径；维数须与模型实际输出一致，应用不请求降维。

向量配置位于 `organization.json` 的独立 `embedding` 节点，完整示例见 [配置示例](config/organization.example.json)。`provider`、`baseUrl`、`model`、`modelRevision`、`dimensions`、`apiKeyEnv`、`timeoutMs`、`topK` 均可配置。密钥填写环境变量名，实际值从后端启动环境读取，修改环境变量后需重启后端。密钥不写入配置或状态响应。默认关闭；旧配置缺少 `embedding` 时自动补默认值。

- 启用后后台补建现有内容；新建、正文修改和回收站恢复会自动排队。文字按 1000 字分段、重叠 150 字，覆盖全文；命中正文末尾时会把该原始片段交给 Agent。
- 图片先由当前 Codex 执行器生成客观描述，再对描述向量化。描述为派生缓存，不写入图片正文或自动创建标签/关系。首次建立图片索引需要可用的 Codex 登录；文本索引独立运行。
- 修改向量服务地址、模型、版本号或维数会自动重建。同名模型更新后需修改 `modelRevision`。补建和重建向量复用已有图片描述。
- 一般失败每项最多尝试三次；修复连接或模型后，可“重试失败项”。登录失效时暂停图片描述生成，保留任务且不消耗重试次数，恢复登录后自动继续；旧版本已标记失败的项目仍需“重试失败项”。退出/关闭功能会取消在途请求；重启继续未完成任务，已完成索引保留。
- 回收站、过期内容及其他模型空间的向量不参与检索；永久删除元素时级联删除对应索引。索引不能使用时，整理器仍可按关键词、标签和最近内容获取候选。

文字和图片描述会发送到所配置的向量服务；图片由所配置执行器分析。相似度是候选排序信号，不代表关系成立的概率，图片相似不会直接生成“来源于某提示词”的关系。

### 更换或升级向量模型

不同模型的向量不能直接混合比较，即使输出维数相同。查询和索引必须采用匹配的模型版本与处理方式。[Ollama 使用说明](https://docs.ollama.com/capabilities/embeddings)。本项目把服务类型、地址、模型名、`modelRevision`、维数和分段格式版本组成索引标识；标识改变后旧向量立即退出检索，已有内容重新排队生成向量。在途旧任务也不能覆盖新索引。

- **换模型**：先下载或部署新模型，再保存新模型名及实际输出维数。例如从 `bge-m3` 换到 `qwen3-embedding:0.6b`，即使两者都是 1024 维，也会重新索引。
- **同名模型升级**：先关闭语义检索并保存，更新模型后修改“向量模型版本”（例如从 `1` 改成 `2`），再启用并保存。这个版本号由用户维护，应用目前不会自动检测服务端权重变化；只更新 Ollama 模型而不改版本号可能混用新旧向量。
- **重建期间**：检索只使用已完成的新索引，候选覆盖范围会逐步恢复；关键词、标签检索继续可用。索引重建保留原文、图片、标签、关系和缓存的图片描述。
- **切回旧模型**：确认旧模型仍可调用，恢复对应配置后重新构建；目前不保留多套可立即切换的完整索引，不能瞬间回滚到旧索引。索引失败可查看错误并重试。

向量生成方式有变化（例如未来加入模型专用的查询/文档前缀、调整分段或归一化规则）时，也必须更新索引标识并重建。更平滑的升级可在后续实现模型权重指纹检测，以及新旧索引并存、验证完成后切换；这些尚不是当前功能。

验证使用真实 SQLite 扩展、HTTP 服务和执行器子进程 fixture；fixture 只验证索引/检索流程，不代表真实模型检索质量。设计及验证记录见 [语义检索设计](docs/semantic-retrieval-design.md)。

## 局域网共享

点击 App 统一的“设置”入口（内容库侧栏），在“局域网共享”配置分区中，可即时开启或关闭完整访问入口，修改访问端口，并保存“启动 App 时自动开启共享”。默认关闭，默认共享端口为 8766；即时开关仅影响本次运行，自动开启配置独立保存。更换端口前需先关闭共享。

开启后将面板中的 `http://局域网IPv4地址:端口/` 复制到同一网络的手机或电脑浏览器。支持搜索、标签筛选、查看图片、文字及关联，在详情中下载原图或 UTF-8 文本。共享无需登录，知道地址的局域网设备拥有与本机相同的全部应用权限，包括编辑、删除、导入、回收站、画布、Agent 会话、自动整理、语义检索、Token 用量和设置。会话记录及中间图片也可访问，操作直接作用于同一份本机数据。关闭共享或退出 App 后停止访问，正在下载的连接也会关闭。

配置保存于数据目录的 `lan-sharing.json`，可在退出 App 后编辑，例如 `{"autoStart":false,"port":8766}`。端口占用、无权限或配置错误会在共享面板显示，本机 App 仍可使用。开发模式共享页使用 `dist/renderer`，前端修改后需先运行 `npm.cmd run build`。

设备需在同一局域网，Windows 防火墙需允许共享端口的专用网络入站访问；本工具不会自动修改防火墙或路由器。入口使用 IPv4 地址，不注册域名；网卡地址变化后重新打开设置获取地址。

## Wiki 备份与文件检查

升级采用独立版本记录和新增表，保留已有 Wiki 内容。备份前关闭桌面及后端，复制完整 `data/`；恢复时使用对应版本的数据库和文件目录。回退代码前另存新版数据，避免覆盖升级后新增的内容。不要只备份 SQLite 而遗漏 `assets/`。

关闭应用后可检查原图缺失和崩溃遗留的无引用文件。默认只读，不运行数据库迁移，不删除文件；回收站图片仍属于有效引用。`unknown` 文件会保留。

```powershell
node tools/wiki-assets.mjs
node tools/wiki-assets.mjs --data-dir "D:\path\to\data"
```

只有确认应用已关闭且检查结果确实为遗留文件时，才执行 `node tools/wiki-assets.mjs --apply --offline`。这个命令仅删除无引用的原图或临时文件，不会删除元素或回收站内容。缺失原图需从备份恢复。

便携版使用可执行文件所在目录的 `data/`；其他打包启动使用 Electron 用户数据目录下的 `data/`。`APP_DATA_DIR` 可指定现有数据目录；程序不会自动搬迁旧数据。`NODE_BINARY` 可显式覆盖后端运行时。
