# 聊天引擎

设置 → Agent 连接 → 聊天引擎可选择 **Codex** 或 **Grok Build**，保存后点击“检测聊天连接”，也可到 Agent 对话检测连接。第一版为全局选择，应用于后续聊天请求；运行中的请求使用提交时的配置。自动整理、图片描述和视频画面分析使用「自动整理与检索 → 模型、超时与语义检索」里选择的执行器，可以是 Codex 或 Grok Build。语义检索的向量服务仍单独配置。

Grok 默认查找本机 `grok`，会优先尝试用户目录下的 `.grok/bin/grok.exe`（其他系统为 `grok`），再使用 PATH。也可填写本机程序路径；不支持 UNC 网络路径或 cmd/bat 启动器。先在终端运行 `grok login`。聊天默认模型可单独配置，与生图执行器的调度模型配置分开；会话中的模型菜单来自 Grok ACP 返回的账号模型列表。

## 普通聊天与生图

聊天引擎决定谁理解要求并调用工具，生图方式决定由谁执行图片任务。

| 聊天引擎 | 生图方式 | 执行方式 |
| --- | --- | --- |
| Codex | Grok Build | Codex 调用应用生图工具，由独立 Grok CLI 请求生成 |
| Grok Build | Grok Build | 同一 Grok 会话直接调用 image_gen / image_edit |
| Grok Build | ChatGPT 网页版 / ComfyUI | Grok 通过应用工具调用所选生图执行器 |

Grok 普通聊天下，原来保存的默认 Codex 生图选择会解释为 Grok 会话生图；界面显示 Grok Build。要连续出图、改图，选择 Grok Build 生图并关闭“原文直发生图”。例如先说“画一只猫”，下一轮只说“把刚才的猫改成白色”，无需手动附上结果图。

“原文直发”仍使用之前的独立生图适配器，跳过持续聊天。因此它每次创建独立 Grok 请求，不续接当前聊天引擎会话；直发后的图片会进入本地聊天记录，下一次恢复普通聊天时补入历史。

## 会话与工具边界

每个本地聊天维护独立 Grok ACP 会话。活跃连接内复用该会话，空闲回收或重启后使用 `session/load` 恢复；加载时不把 ACP 重放消息再次写入本地聊天。已有本地线程字段保存不透明的引擎会话编号，请求记录同时保存引擎和工具/指令签名，只有同一引擎、同一配置且对应最近轮次时才复用。切换引擎、执行器或分支会重建上下文，只重放当前分支的本地历史。

应用会把当前分支上一张图片复制到聊天工作目录，并在本轮上下文提供真实路径，避免模型手工拼接 Grok 内部百分号编码目录。用户从图片查看器指定的原图优先于自动提供的上一张结果。原图已不可用时说明错误，不把重新创作冒充成功改图。Grok 原生输出需属于当前 Grok 会话，校验后复制到聊天目录，再沿用图片展示、归档、保存到 Wiki 和选区编辑流程。

Wiki、文件读取和外部生图通过只绑定 `127.0.0.1` 的会话专属 HTTP MCP 桥接到现有工具处理器。随机令牌仅用于活动连接，不写入项目的调用记录；请求仍执行原有的工具名称、活动轮次、资料版本和建议采纳检查。Grok 原生工具事件记录实际输入；不把上下文、模型推断或不存在的计数冒充调用参数或用量。

ACP 不采用 TUI / headless 的 `--tools` 过滤，因此适配器要求本机 Grok 提供客户端 `pre_tool_use` 门禁。每次执行前只允许所选图片工具、工具发现和 `self_wiki` 应用工具；拒绝原生 Shell、原生文件工具、其他 MCP、子 agent 及失败后的同轮图片重发。门禁支持缺失时连接检测失败，不静默启动完整 coding agent。停止发送 `session/cancel`，必要时关闭本次专属进程；不会自动重发状态未知的请求。已经提交的远端图片任务可能继续。

## 验证

- `test/integration/grok-chat.test.js`：旧配置升级、MCP 令牌与工具边界、会话续接、重启加载、自动改图引用、分支隔离、停止和非法图片结果。
- `test/ui/grok-chat.test.js`：从设置选择聊天引擎，普通聊天出图，刷新后不附图续改。
- 本机 Grok Build 1.0.70 实测：通过 Wiki 工具读取资料 → 同一会话文生图 → 重启应用 → 仅文字指令把橘猫改为白猫；另用无害 Shell 请求验证客户端门禁在执行前拦截。

新适配器位于 `src/agent/executors/grokSession.js`、`grokProcess.js` 和 `grokTools.js`。应用连接池选择聊天适配器，业务层继续管理历史、附件、工具调用和归档。无需数据库迁移，旧配置默认 Codex。
