# 聊天生图方式

会话输入框旁可选择 **Codex CLI**、**ChatGPT 网页版**、**ComfyUI**或 **Grok Build**，每个会话独立保存。新会话沿用最近选择。设置 → Agent 与检索只管理服务连接；ComfyUI 默认地址为 `http://127.0.0.1:8188`。进行中的请求使用提交时的快照。

## 配置 Grok Build

若希望由 Grok 理解整段对话并自动连续改图，同时在设置 → Agent 连接选择 **Grok Build 聊天引擎**，并关闭“原文直发生图”。该模式在同一个 Grok 会话内生图，详见[聊天引擎说明](chat-engines.md)。下文的独立执行器行为适用于 Codex 调用 Grok 生图或原文直发。

1. 安装本地 Grok Build，先在终端运行 `grok login` 完成登录。应用沿用本机账号，不读取或保存账号令牌。
2. 在设置 → Agent 与检索展开“Grok Build 连接”。程序名默认 `grok`，会先尝试用户目录下的 `.grok/bin/grok.exe`（其他系统为 `grok`），再从 PATH 查找。也可填写本机程序完整路径；不支持网络路径和 `.cmd` / `.bat` 启动器。
3. 调度模型默认 `grok-4.6`，需为账号当前可用的模型。这是负责调用图片工具的模型，实际图片模型由 Grok Build 管理。保存后可检测程序版本；检测不生成图片，也不保证登录、额度或生图权限可用。
4. 会话生图方式选择 Grok Build，并选择比例。支持自动、`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`2:1`、`1:2`、`19.5:9`、`9:19.5`、`20:9`、`9:20`；比例与执行器随会话保存，并固定在本轮快照中。

没有参考图时调用 Grok 的 `image_gen`。附参考图时调用 `image_edit`，支持风格转换、换色、增删元素、多图融合，以及引用上一张生成结果连续改图。每次最多 8 张 PNG/JPEG/WebP 参考图，每张最多 25 MiB，限当前会话目录。Grok 可能缩小参考图，细节和文字保真不保证。单图编辑忽略所选比例，保留原图比例；文生图和多图编辑使用所选比例，实际像素尺寸以结果为准。

原文直发跳过现有 Codex 的提示词整理，将原文和按顺序拼接的文字素材交给 Grok Build；Grok 仍负责调用图片工具，工具实际参数保存在调用详情中。每次独立创建 Grok 会话，不隐式续接上一次 CLI 上下文；连续改图需引用待修改图片。图片查看器选区以视觉指示图传入，不是像素级蒙版。当前 CLI 图片工具没有种子、批量张数、精确尺寸、透明背景开关或蒙版参数，需要多张时逐次调用。

适配器使用无界面 CLI 和 streaming-json，限制为本次所需的 `image_gen` 或 `image_edit`，关闭网页搜索、子 agent、动态工具发现与自动更新。每次返回一张图片，校验结果来自本次 Grok 会话后复制到当前聊天目录，再复用图片展示、归档和保存到 Wiki。详情展示实际工具参数、Grok 会话编号和 CLI 返回的用量（不将其视为完整生图账单）。待执行工具事件只表示调用意图，成功结果才确认提交完成。

最多等待 30 分钟；登录刷新失败、限流、拒绝、协议错误或结果丢失均不自动重发、不切换其他后端。停止会终止本次本地进程，已提交的远端任务可能继续，可在本机 Grok 会话中检查。适配器通过 JSON 事件解析结果，不读取历史聊天推测图片路径。

`test/integration/grok-build.test.js` 用模拟 CLI 进程验证参数、路径边界、错误、取消、会话选项与图片归档；`test/ui/grok-build.test.js` 验证设置检测、会话比例、直发、调用记录和刷新恢复。已用本机 Grok Build 1.0.62 实测文生图（4:3，1152×864）、单参考图编辑，以及双参考图融合（16:9，1280×720）。

未开启“原文直发生图”时，聊天、检索和 Wiki 工具继续使用现有 Codex app-server。选择网页版或 ComfyUI 时，应用关闭该进程的原生图片工具，并注册对应的 `generate_image`。切换方式会重建模型线程并补入当前分支历史，保留本地聊天和图片。

## 配置 ComfyUI

基础版连接用户自行运行的 ComfyUI 服务，使用其[原生 HTTP API](https://docs.comfy.org/development/comfyui-server/comms_routes)，无需修改 ComfyUI 源码。

1. 在 ComfyUI 中准备并运行一个生图工作流，确认模型和节点已安装，每次输出一张图片，保存工作流。需要使用会话图片时，所选输出依赖中应只有一个 `LoadImage` 图片入口。
2. 在设置 → Agent 与检索填写 ComfyUI 地址，保存后检测连接。检测只读取服务信息，不提交任务。支持带路径前缀的 HTTP(S) 地址；暂不支持鉴权或多用户账号选择。
3. 在会话输入框旁选择 ComfyUI，打开“工作流与参数”，从服务端已保存的工作流列表选择。读取的是 ComfyUI 默认用户的 `workflows` 目录，浏览器中尚未保存的画布不会显示。
4. 检查提示词写入字段和图片输出节点；有明确候选时自动选择，有歧义时手动指定。只执行所选输出及其依赖。
5. 在面板中调整尺寸、种子、步数等参数；“更多参数”包含节点声明的模型列表、负面提示词等。点击“应用到本会话”。映射和参数会随会话保留，也会记住该工作流最近的选择。
6. 直接输入生图要求让 AI 调用，或开启“原文直发生图”把文案直接交给当前 ComfyUI 工作流。只发一张图片、文字留空时，沿用工作流中所选字段的原有提示词；填写文字或选择文字素材时，用这些文字替换该字段。图片、进度和调用记录使用现有会话流程。

通过 ComfyUI 的 `/userdata` 和 `/object_info` 接口发现与转换普通保存工作流，无需修改 ComfyUI。支持普通节点、连接、转接节点、旁路节点和常见种子控制。旁路按插槽类型连接上游；静音或旁路后没有有效来源的可选输入会被省略，必填输入仍会明确报错。自定义前端序列化、PrimitiveNode 和子图可能无法自动转换，会明确报错。可在会话面板的备用入口导入 [API 格式工作流](https://docs.comfy.org/development/api-development/workflow-api-format)，无需在设置页维护模板。工作流最多 512 KiB、1000 个节点。

选中的工作流被缓存为不可变版本，记录原服务地址。发送时保存版本、映射和参数；远端修改不会改变已经提交的生成。点“更新当前工作流”读取新版本并重新检查映射。修改设置中的地址后，也应重新选择或更新工作流；已选版本继续指向面板显示的原地址。远端读取完成后才写入数据库，SSE 仅传递轻量的版本引用和选项。

种子使用面板中的数值，不执行 ComfyUI 浏览器的“生成后随机化”。每轮最多上传一张粘贴图片或 Wiki 图片，通过 ComfyUI 的 `/upload/image` 保存到 `input/self-wiki`，以唯一文件名替换当前输出依赖的 `LoadImage.image`；不修改保存的工作流，也不覆盖已有图片。没有图片入口或有多个入口时明确报错，不猜测映射；未附图时保留工作流已有的图片配置。选区蒙版和批量结果尚未接入，返回多张图会报错。参数只能覆盖工作流中已有的标量控件，不能覆盖连线。调用详情记录实际提示词、提示词来源和上传图片对应的节点、文件名及摘要。上传失败时不提交生成，上传和生成均不自动重试。

ComfyUI 请求由 Wiki 服务端发起，浏览器不直接连接 ComfyUI。生成提交一次后，通过任务 ID 查询排队、执行和完成状态，再下载所选输出节点的图片；首版不显示采样步数。调用详情记录实际服务地址、任务 ID、请求关联 ID、工作流名称和摘要；本轮请求保留生图选项。网络读取失败可重查原任务，提交请求不自动重试；提交响应丢失时明确提示状态未知，应先在 ComfyUI 查看，手动重试会创建新任务。

每次最多等待 30 分钟。停止或超时优先通过新版 `/api/jobs/{id}/cancel` 取消本次任务；旧版不支持时只删除本次排队项，已经运行的任务可能继续，可到 ComfyUI 查看。应用不调用全局中断，避免影响其他任务。请求尚未取得远端确认就断线或服务重启时，不能保证取消远端执行。

`test/comfyui.test.js` 使用模拟 HTTP 服务验证工作流读取与转换、参数校验、会话隔离、重试/分支/编辑与重启恢复、错误和取消隔离，以及浏览器设置和会话交互，不依赖真实 GPU。真实模型和自定义节点的兼容性需配置用户服务后再做一次实际生成验证。

## 配置网页版

1. 安装 Python 3.10 或更新版本，在设置中填写程序名或绝对路径。
2. 按 [chrome-use 安装说明](https://github.com/leeguooooo/chrome-use#install) 安装浏览器工具。Windows 可从该项目 Releases 下载 `chrome-use-win32-x64.tar.gz`，解压后在设置中填写 `chrome-use.exe` 的完整路径。也支持 JavaScript 入口文件；不执行 `.cmd` / `.bat` 启动器。
3. 按 chrome-use 的扩展连接说明连接 Chrome，并在这个 Chrome 中登录 ChatGPT。
4. Chrome 配置名称保持 `relay`，保存后点击“检测网页版生图连接”。检测检查 Python、浏览器工具和扩展连接；登录和生成能力在真正生成时检查。

配置保存在数据目录的 `organization.json`：

```json
"imageGeneration": {
  "executor": "chatgpt-web",
  "chatgptWeb": {
    "python": "python",
    "browser": "C:\\Tools\\chrome-use\\chrome-use.exe",
    "profile": "relay"
  }
}
```

浏览器连接独立于 Codex 桌面内置的浏览器。连接后，生成提示词和选用参考图会发送到当前 Chrome 登录的 ChatGPT 账号；无需在 Wiki 中填写该账号的 Cookie 或访问令牌。

## 运行行为

- 每次调用返回一张图片。网页版请求在本应用中排队执行，每张最多等待 30 分钟；尺寸作为构图要求提交，实际尺寸以结果为准。
- 编辑已生成图片时必须引用用户选择的原图。参考文件仅限当前会话工作目录，每次最多 8 张、每张最多 25 MiB，并在全部上传确认后提交提示词。
- 生成结果使用现有图片展示、保存到 Wiki、后续改图和调用记录功能。记录区分模型提供的提示词和准备提交到网页的完整文本。
- 工具进度会显示打开网页、输入提示词、等待生成和取回图片。只有在网页中确认出现对应用户消息后，才记录为“已提交”；生成前的提示词准备不算提交成功。
- 网页登录失效、限流、拒绝或超时会作为工具错误返回，不自动切换到其他生图方式。选择网页入口不能保证某个请求会通过审核。
- 若 ChatGPT 显示 `Content failed to load` 等整页错误，执行器停止等待并返回原对话链接。先重新加载这个已有对话查看结果，避免重新发送同一提示词。
- 停止会取消排队或终止本地执行；已经提交到网页的生成可能继续完成，可到 ChatGPT 查看。
- 保留生成的 ChatGPT 对话，成功或失败后关闭本次工具使用的标签页。

## 上游与验证

复用 [leeguooooo/chatgpt-imagegen](https://github.com/leeguooooo/chatgpt-imagegen) 的网页版后端。源码按固定提交保存在 `src/agent/executors/vendor/chatgpt-imagegen/`，附 MIT 许可证和 SHA-256；不自动更新。宿主通过 Python JSON 行协议调用 `run_web`，显式使用 chrome-use 的 `--json` 输出并解析 `data.result`。Windows 下使用临时文件接收命令输出，避免后台浏览器进程继承管道句柄导致调用不结束。接入层还检查参考图完整性、取消和错误记录。Codex CLI 生图继续沿用现有 app-server 集成。

`test/chatgpt-web.test.js` 使用真实 Python 和固定上游源码、模拟 chrome-use 进程边界，覆盖出图、上传确认、限流、路径限制和取消。聊天集成及设置界面也有回归测试。这些测试不验证真实 ChatGPT 页面选择器或账号状态；升级上游或 chrome-use 后，应再用已连接的真实浏览器生成一张普通测试图。

## 原文直发生图

发送框旁的“原文直发生图”使用会话选中的 ComfyUI 或 ChatGPT 网页版，不调用 Codex 整理提示词。在 Codex CLI 下打开开关会显式切换下拉框为 ChatGPT 网页版；关闭后使用当前所选执行器的 AI 辅助流程。开关与执行器随会话保存。以下网页对话和参考图行为仅适用于 ChatGPT 网页版。

文案保留空格、换行和原字句；选中的文字素材按顺序以两个换行分隔，接在文案之后。选中的图片使用原尺寸像素，沿用应用的 PNG 格式处理；不发送缩略图、自动图片描述、标签或关联信息，也不重复拼接本地历史；网页会保留绑定后在该网页对话内产生的上下文。剪贴板附件使用加入会话时保存的图片。最多 8 张图片，合并文本最多 12000 字；没有文案或超限时直接报错，不自动补写或截断。文案需自行写明生图要求；这里只取消应用侧的加工，ChatGPT 网页仍会正常理解和处理请求。

同一本地会话的网页版生图会持续使用已绑定的 ChatGPT 对话，首次提交后保存网页地址，重启后继续复用。直发和 AI 辅助网页版生图共用该绑定。CLI 中间轮次不会自动补发到网页。编辑旧消息、切换历史版本或创建分支后另建网页对话，避免混入其他分支的后续内容；新网页不会自动重放旧历史。旧版本创建但未保存地址的网页对话无法自动关联，升级后首次发送会新建绑定。网页丢失或仍在生成时明确报错，不自动改用新对话。取消或失败后已取得的网页地址仍会保留，便于下一轮继续；重试发送的是一条新消息，不会撤销网页已有消息。

每次直发提交一轮生图请求，结果、进度、停止操作和失败原因仍显示在会话中。“查看本轮请求”保存拼接后的实际文本和图片顺序。编辑直发消息时沿用直发模式；开关关闭后新消息恢复普通 AI 辅助流程。图片查看器里的选区编辑仍使用原有编辑流程。

## 执行器模块与接口

生图执行器分为两种模式：`native` 在模型会话内执行，`tool` 由应用调用。Codex CLI 使用 native，ChatGPT 网页版和 ComfyUI 使用 tool。旧 API 请求未指定会话生图选项时，保留原全局配置和直发到网页版的路由。数据库迁移 36 增加会话选项、轮次快照、偏好和工作流缓存；旧消息保留原记录。

- `src/shared/domain/imageGeneration.js` 定义执行器标识、名称、调用模式、原文直发能力和配置校验，会话选择器与 Codex 图片工具开关共用这些定义。
- `src/server/application/chatImageExecutor.js` 选择执行器、固定本轮配置快照，并把需要持久化的会话状态绑定到当前聊天分支。`chatImageSettings.js` 读取远端工作流、校验选择并解析本轮执行配置；显式会话选择优先于旧全局配置。
- `src/agent/executors/chatgptWeb.js` 拥有工具 schema、模型指令、Python 协议、排队、参考文件检查、进度转换、网页会话续接及取消。适配器只拿到会话状态的读写回调，不持有数据库或聊天服务。
- `src/agent/executors/comfyui.js` 拥有工作流生图工具、提示词默认值、图片上传、任务查询、下载与取消；`comfyuiApi.js` 处理有界 HTTP 请求，`comfyuiWorkflows.js` 读取节点定义并转换已保存的画布。`src/shared/domain/comfyui.js` 校验 API 工作流和映射；`ChatImagePicker.jsx` 管理会话选择与参数。
- `chatService.js` 负责素材准备、编辑原图约束、工具调用记录和图片归档。它按执行器模式调用工具，不解析网页协议。生图配置界面独立在 `ImageGenerationSettings.jsx`，调用记录按执行器定义展示名称和提示词来源。

外部适配器提供以下接口，工厂绑定配置与会话状态后交给聊天层使用：

```js
{
  tool,         // generate_image 工具定义；输入能力和限制在 inputSchema 中声明
  instructions, // 此执行器的模型使用说明
  probe(config, workspace), // Promise<{ available, message, ...实际诊断信息 }>
  generate(request, {
    config, workspace, signal, onProgress, verbatim, continuation
  }) // Promise<{ bytes, savedPath }>
}
```

`request` 的具体参数由适配器的 schema 与运行时校验负责：网页版使用 `prompt`、`referencePaths` 和 `size`，ComfyUI 接受 `prompt` 和可选的单张 `referencePaths`，空白 `prompt` 表示沿用工作流中的提示词。`referencePaths` 指向当前聊天工作目录中的文件，`savedPath` 也必须在该目录内。每次返回一张图片，聊天层统一校验、转成 PNG 并归档。`verbatim` 仅用于声明支持原文直发的执行器。Codex 原生模式不提供独立的 `generate/probe`，继续由模型会话管理调用、诊断和结果事件。

`onProgress` 的事件契约为：

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `progress` | `message` | 可直接显示的进度文案 |
| `prepared_prompt` | `prompt` | 执行器准备发送的完整提示词，不代表提交成功 |
| `submitted` | `message` | 执行器已实际确认提交，应用记录确认时间 |
| `metadata` | `metadata` | 适配器的补充执行记录；网页版保留 `conversationUrl`，ComfyUI 使用 `comfyui` 对象记录任务及模板信息 |

需要续接外部会话时，应用层提供 `continuation.read/save`。网页版必须取得排队位置后再读取最新绑定，并在收到地址时立即保存，失败或取消后也能保留已经取得的地址；分支版本校验仍由原有仓库方法负责。`metadata` 仅补充记录，不得覆盖通用的输入、输出和提交状态字段。

停止信号传递给执行器，聊天停止和应用退出等待已发起的生图调用结束。失败不自动切换后端或重试提交。切换执行器会重建模型线程并补入本地历史，即使两个执行器使用同样版本的动态工具也不能复用旧线程。

后续增加执行器时，新增执行器定义、专属配置与设置项，并在应用层注册适配器。后端协议和任务进度留在适配器内；无需向聊天服务增加具体后端分支。更丰富的参数、批量结果或蒙版能力应在有实际工作流时再扩展契约。
