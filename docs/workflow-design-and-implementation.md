# 通用工作流：产品设计与实施方案

日期：2026-10-27
适用项目：self-wiki
状态：设计定稿；首版实现已接入，使用方式与当前验证边界见 [工作流指南](workflows.md)。文中默认值为本方案的设计决策，后续可通过版本演进调整。

## 1. 目标与核心决策

新增独立的「工作流」模块，用户通过节点、连线、参数和变量，自行组合素材处理与 AI 创作流程。「批量图片反推 → 生图」是内置示例，不是写死的业务流程。

核心目标：

- 能从空白画布搭建流程，也能复制示例修改。
- 模型调用、图片生成、批量处理和结果保存自由组合。
- 节点结果可以查看、修改、复用；失败后不必从头执行。
- 多张图片之间的数据对应关系明确，不能依赖聊天上下文猜测。
- 运行历史在刷新、关闭界面或后端重启后仍可查询。
- 新节点通过注册表扩展，不要求改写调度器。

确定采用：有类型的节点端口、显式变量绑定、各作用域内有向无环图（DAG）、受控的批量循环、SQLite 持久化运行记录、后端执行。

首版限制节点种类，不限制用户自由组合这些节点。不给用户强制套用「反推」「生图」等固定步骤。

首版不包括任意 JavaScript/Shell 执行、任意 HTTP 请求、第三方插件加载、定时触发、多人协作、无限循环、自动决定工具调用的通用 Agent 节点。需要这些能力时另行设计权限与执行契约。

## 2. 已核实的仓库基础

以下为当前工作区事实，实施时应再次核对；工作区已有大量其他变更，本方案不要求回滚、整理或覆盖它们。

| 现有能力 | 仓库依据 | 复用边界 |

现有 Grok 接入包含“提交状态未知不自动重发”的处理。工作流必须保留此语义，不能把所有超时都归类为可重试失败。

本方案基于本地适配器契约，不宣称外部服务的当前模型、额度、并发或功能范围。实施时以能力探测和真实小样本验证为准，不在设计中固定模型名称。

## 3. 产品概念

| 概念 | 定义 |
| --- | --- |
| 工作流 | 用户命名、维护的流程，拥有可编辑草稿 |
| 工作流版本 | 一份不可变的流程定义；每次运行引用确定版本 |
| 节点 | 一项能力及其配置，例如模型调用或保存 |
| 端口 | 节点公开的有类型输入、输出 |
| 绑定 | 输入来自常量、运行参数或上游端口的规则 |
| 运行 | 某版本在一组固定输入下的一次执行 |
| 节点实例 | 某节点在具体循环项中的一次逻辑执行位置 |
| 尝试 | 节点实例的一次实际执行；重试新增记录 |
| 产物 | 文本、JSON、图片等不可变结果，带来源信息 |
| 子图 | 批量循环内部的一组节点；不是独立聊天会话 |

节点显示名可任意修改，引用使用稳定 ID。画布坐标、颜色、折叠状态只影响展示，不改变执行结果。

## 4. 用户体验

### 4.1 入口与页面

侧栏增加「工作流」。列表页显示名称、更新时间、最近运行状态，支持新建、复制、归档和查看运行历史。

编辑页包括：

- 左侧节点库：搜索、分类、拖入画布。
- 中间画布：连线、框选、复制粘贴、撤销重做、节点分组和循环容器。
- 右侧配置：输入绑定、模型与参数、校验错误、输入输出预览。
- 底部运行面板：节点状态、事件、批次表和产物预览。

工具栏提供保存、校验、运行、选样试跑。运行前的输入表单由输入节点自动生成。

编辑视图和运行视图明确分开：编辑草稿不会改变已开始的运行。历史运行展示当时的图与配置；选择“用此版本编辑”创建草稿副本。

### 4.2 连线和变量

连线连接输出端口与输入端口；类型不兼容时立即提示，后端仍做权威校验。

配置字段提供“固定值／引用变量”选择器。变量选择器按节点显示名称呈现可用输出，底层保存节点 ID、端口和字段路径，不保存依赖显示名的字符串。

提示词支持固定文字和变量片段混排。编辑器保存模板片段 AST，例如文字片段和 `ref` 片段；首版不执行表达式、不使用 `eval`，不对模型输出进行第二次模板展开。

### 4.3 批次与检查

循环结果表每行对应一个稳定的输入项 ID，显示原始素材、选定节点的输出、状态、错误和操作。顺序按输入列表保留，不随完成时间变化。

人工检查节点显示待检查内容，用户可以接受、修改后接受、拒绝。拒绝使该执行路径取消，下游不运行；其他循环项继续。修改结果产生新产物，保留原始模型输出和操作记录。

支持逐项检查以及明确选中若干项后批量接受；不会把等待超时当作默认接受。

## 5. 节点与数据类型

### 5.1 数据类型

首版支持 `text`、`number`、`boolean`、`json`、`image`、`list<T>`，并区分可选输入与必填输入。`json` 与 `text` 不隐式互转，单个 `image` 与 `list<image>` 通过显式“组成列表”操作转换。

图片值采用服务端管理的产物引用：产物 ID、内容哈希、MIME、尺寸、来源。前端不传任意服务器文件路径作为图片输入。大文本、图片字节不写入图定义或事件。

同一个输入端口仅有一个绑定；需要合并多个来源时使用列表或数据处理节点。输出可以连接多个下游。

### 5.2 首版节点目录

| 类型 | 输入与配置 | 输出 | 说明 |
| --- | --- | --- | --- |
| 输入 `input` | 参数名、类型、默认值、是否必填 | 声明类型的值 | 文字、图片、图片列表；选取资料库素材时固定顺序 |
| 提示词模板 `template` | 模板片段、变量绑定 | `text` | 可引用文字资料；运行时冻结其内容 |
| 模型调用 `model` | 指令 `text`、图片 `list<image>`、执行器配置 | `text` 或校验后的 `json` | 首先实现 Grok 的受限文本输出调用 |
| 图片生成 `image.generate` | 提示词 `text`、参考图 `list<image>`、执行器参数 | `list<image>` | 不保证所有后端都支持相同参数 |
| 数据处理 `transform` | 有限的声明式操作 | 声明类型的值 | 字段提取、文本拼接、组成列表、取第 N 项、列表配对 |
| 批量循环 `foreach` | `list<T>`、显式捕获的外部输入、子图 | 逐项结果列表 | 第一版只允许一层循环 |
| 人工检查 `review` | `text` 或 `list<image>` | 接受后的同类型值 | 文字可编辑；图片可选择子集，不在此节点编辑像素 |
| 预览 `preview` | 任意受支持类型 | 原值 | 在运行内展示，不写入内容库 |
| 保存 `library.save` | 文字或图片、标签、明确来源 | 元素 ID 列表 | 一次保存一个文字产物或一组图片；保持来源链 |

第一版包含以上最小数据处理能力，避免用户连线后还要依靠聊天完成字段转换。条件分支、汇合、可复用子工作流和更多输出方式列入第二阶段，不在第一版节点库展示未实现入口。

### 5.3 模型及生图执行器

节点通过执行器 ID 和配置引用选择服务；运行快照保存模型、非敏感参数和适配器版本。凭证仅由后端读取，不复制进图定义、运行记录或导出文件。

执行器注册表声明能力：输入图片数、格式、输出类型、支持参数、是否可查询远端结果、并发资源键、是否支持取消。提交前按实际能力校验，不能静默忽略种子、比例等参数。

Grok 反推使用隔离的单次上下文，并在适配层明确关闭生图、Shell、Wiki 修改等工具；不能只靠提示词要求“不要生图”。结构化输出由应用校验；无效输出保存原文并使节点失败，不静默交给下游。

图片生成直接使用上游提示词，不额外调用模型改写。若用户需要润色，应增加显式模型节点。对于经模型调度工具的执行器，同时记录请求提示词和可观测的实际工具参数，不承诺不可证明的逐字执行。

首版验证并开放 Grok 生图与 ComfyUI（有图片输入的流程必须具备有效映射）。ChatGPT 网页版与 Codex 原生生图暂不出现在工作流可选列表，待独立生命周期和并发契约完成后再注册。

## 6. 图定义与执行规则

### 6.1 定义结构

定义包含 `schemaVersion`、节点、输入绑定、输出声明、循环子图和展示布局。每个节点包含稳定 ID、类型、节点契约版本、配置和作用域。

**输入绑定是数据依赖的唯一权威来源。** React Flow 的线由绑定派生；导入导出不额外维护另一份可能不一致的业务边集合。模板中的变量引用也进入同一个依赖提取器。

绑定的逻辑形式：

```json
{
  "kind": "output",
  "nodeId": "describe",
  "port": "text",
  "path": []
}
```

首版只允许结构化字段路径，不允许任意代码表达式。输出结构为 JSON 时，字段提取节点声明期望类型，执行时验证字段存在及类型。

### 6.2 图校验

保存允许保留未完成草稿；运行必须通过完整校验：

1. 节点 ID 唯一，节点类型及契约版本受支持。
2. 引用存在，类型匹配，必填输入已绑定。
3. 每个作用域是 DAG，无自环、跨作用域非法引用。
4. 循环内部只能读取 `item`、`index`、`itemId` 与显式捕获输入；外部不能直接引用循环内部节点。
5. 模型连接、素材存在性、图片数量和格式符合执行器限制。
6. 图规模与展开规模在上限内，并显示预计最大模型／生图调用次数。

初始默认上限：每作用域 100 个节点，整个定义最多 300 个节点，单次循环 1000 项，总节点实例 20000。上限属于后端配置；超限报错，不截断输入。实际内存与响应时延需通过性能测试验证后再调整。

### 6.3 调度

后端调度器只调度依赖已满足的节点；独立分支可以并发。默认全局外部请求并发 2、每个执行器资源键并发 1，所有工作流运行共享限制。与现有聊天共用受限外部资源时，须在公共执行器层共用资源锁，不能只在单次运行内限流。

数据库事务只用于抢占、状态变更、事件和产物引用提交；网络调用、进程等待和文件处理都在事务外执行。

队列持久化，不以一个未等待的 Promise 作为任务存在的唯一依据。当前部署按单后端实例执行，启动时持有调度所有权；不设计分布式 Worker。

### 6.4 批量循环

循环输入在启动时固定，产生稳定项 ID；运行中不重新查询动态素材集合。子图按每项独立展开并隔离上下文；采用增量展开与有界排队，避免一次加载全部图片字节。

每个输出项为 `{itemId, index, status, outputs, error}`。失败项保留位置，不因为过滤失败而造成原图和结果错配。循环最终状态为成功、部分失败或失败；只要仍有待检查／未知结果项，就不能宣告完成。

下游处理汇总列表时，必须显式选择“仅成功项”或处理完整结果结构。首版默认单项失败不终止其他项；鉴权失效等服务级故障暂停对应执行器的后续调度。

空列表循环直接成功并输出空结果列表，不调用子图。必填图片输入是否允许空列表由输入节点声明。循环项全部失败时循环失败，部分成功时为部分失败；汇总节点可显式声明接收完整终态结果，其他依赖失败结果的节点保持阻塞。

两组列表配对通过 `zip` 操作，默认要求长度相等；固定参考图通过循环捕获输入广播。全组合与嵌套循环暂不提供，避免隐式放大调用次数。

## 7. 生命周期、重试与恢复

### 7.1 节点状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 尚未满足依赖或等待调度 |
| `running` | 本次尝试已抢占并开始执行 |
| `waiting_review` | 等待人工操作 |
| `succeeded` | 结果及产物引用已持久化 |
| `failed` | 已确认失败 |
| `unknown` | 请求可能已发生，结果无法确认 |
| `blocked` | 依赖失败、拒绝或未知导致不能执行 |
| `cancelled` | 用户明确取消 |

运行状态包括 `queued`、`running`、`paused`、`waiting_review`、`needs_attention`、`succeeded`、`partial_failed`、`failed`、`cancelled`。汇总优先级：显式取消；未知／服务故障需处理；显式暂停；存在可执行或在途节点；仅有待检查项；最后按成功与失败数量终结。状态汇总由服务统一实现，前端不自行推断。

### 7.2 暂停与取消

- 暂停：停止发起新的节点，已开始的节点允许完成并保存；恢复后继续排队。
- 取消：停止新调度，对在途调用尽力取消；本地停止不代表远端未执行。
- 已取消运行仍可记录迟到结果或未知状态，但不启动下游，也不自动保存到内容库。
- 回调必须匹配尝试 ID 与执行代次，旧尝试不能覆盖新尝试的输出。

### 7.3 重试边界

首版不自动重试外部模型／生图调用。用户对确认失败的节点发起重试，创建新尝试，并复用已成功上游。

对于 `unknown`：提供“核查并取回”能力（执行器支持时）和“明确重新执行”操作；后者说明原任务可能已完成并产生额外调用。不能把未知状态直接放入“重试全部失败”。

用户也可以明确放弃未知项：保留旧尝试的未知事实，逻辑节点转为取消，下游阻塞。明确重新执行后当前尝试指针移至新尝试；旧尝试迟到结果仅归档到旧尝试，不替换有效输出。以上操作均记录用户决定，使运行能够终结而不篡改历史事实。

纯本地确定性节点可以恢复执行。图片已落盘但保存入库失败，只重试保存；不重新生图。

请求提交前先持久化尝试 ID、请求摘要和 `dispatch_started`。存在“远端已接收、本地未记录成功”的窗口时，恢复判为未知。除非执行器有可验证的幂等键或结果查询，否则不承诺外部请求恰好一次。

### 7.4 重启恢复

重启后恢复队列、检查点和产物索引。未发起请求的节点可继续；纯本地计算节点可重新计算；保存等有副作用的本地节点先查询幂等回执再恢复；中断的外部调用根据远端 ID 查询，不能查询则标记 `unknown`。人工检查继续等待。

恢复时先取得后端调度所有权、确认旧 Worker 不再拥有有效代次。外部孤立进程可能继续运行，其任务不自动重发。

### 7.5 修改后继续与结果复用

同一运行内重试不能改变节点配置或已固定输入。修改提示词、参考图、参数或节点连接后，创建派生运行并记录父运行及变更。

默认复用不受影响的成功结果；变更节点及所有下游失效。用户选择“重新生成”时显式使目标节点失效，即使参数未变。复用是明确的历史结果引用，不是全局缓存。

复用条件包含节点契约版本、有效配置、输入产物哈希、执行器实现版本和用户覆盖值，且产物仍然存在。第一版用依赖闭包加严格快照比较判定，避免先引入复杂缓存系统。

人工检查的“修改后接受”属于当前运行已定义的交互输入，可以继续当前运行；事后修改已接受结果则创建派生运行。

## 8. 存储、产物与来源

### 8.1 建议数据表

实际字段与迁移编号实施时按仓库现状确定，不在本文件预占版本号。

| 表 | 关键内容与约束 |
| --- | --- |
| `workflows` | ID、名称、草稿 JSON、草稿修订号、归档时间 |
| `workflow_versions` | 工作流 ID、版本号、定义快照、哈希；版本不可变 |
| `workflow_runs` | 版本 ID、输入快照、父运行、状态、控制版本、创建请求键 |
| `workflow_node_instances` | 运行 ID、作用域路径、节点 ID、项 ID、状态、当前尝试；逻辑位置唯一 |
| `workflow_node_attempts` | 实例 ID、尝试号、请求摘要、提交阶段、远端 ID、错误、用量；尝试号唯一 |
| `workflow_artifacts` | 类型、存储键或文字／JSON、哈希、大小、创建者、来源 |
| `workflow_artifact_refs` | 输入／输出／复用引用、所属运行与节点、端口；用于保护共享产物 |
| `workflow_events` | 运行 ID、单调序号、类型、节点／尝试 ID、精简数据 |
| `workflow_save_receipts` | 保存节点、输入产物、目标元素；操作唯一键防止重复保存 |

人工检查决定、编辑后的值和操作者来源作为持久化命令／事件保存；本机单用户场景记录本机操作即可，不虚构用户账号系统。

### 8.2 文件与一致性

工作流使用独立的 `data/workflow-artifacts/` 和 `data/workflow-workspace/`。执行器临时文件在各尝试目录内，校验格式、大小和来源后写入产物存储。文件先写临时位置再原子改名，随后短事务提交产物与节点结果。

文件已写但数据库未提交形成孤立文件，延迟清理；数据库引用的文件缺失则报告产物损坏，不能伪装成功。内容库保存遵循现有媒体去重规则，并用保存回执防止重试创建重复文字或重复来源关联。

输入图片在运行准备阶段复制或固定到工作流拥有的产物，文字保存快照；记录原元素 ID 和内容哈希。源内容后来修改或删除不会改变已准备运行。准备未完成且源文件缺失时阻止启动。

运行保存、文件落盘与内容库写入采用可恢复的小步骤，不持有跨网络事务。内容库元素及保存回执能同事务提交时应一起提交；否则需要可查找的唯一来源键进行恢复。

### 8.3 来源与清理

最终产物能追溯到工作流版本、运行、节点、输入原图、提示词产物、参考图和执行器参数。请求提示词、模型原始回答、人工改写及实际工具参数分别保存，不能互相冒充。

工作流删除采用归档，不删除历史运行。首版不自动清理历史产物；运行清理为明确操作，只删除无输入／输出／派生引用的文件。待检查、在途、未知任务所需文件不能清理。已经保存到内容库的文件和元素不随运行删除。

## 9. API 与权限

建议接口：

| 接口 | 行为 |
| --- | --- |
| `GET /api/workflow-node-types` | 返回节点契约与可用执行器能力 |
| `GET/POST /api/workflows` | 列表／创建 |
| `GET/PUT /api/workflows/:id` | 读取／按草稿修订号保存 |
| `POST /api/workflows/:id/validate` | 完整校验，返回字段定位与调用次数上界 |
| `POST /api/workflows/:id/runs` | 冻结版本与输入，创建运行 |
| `GET /api/workflow-runs/:id` | 运行快照、节点状态和分页结果 |
| `GET /api/workflow-runs/:id/events?after=...` | 按游标分页增量事件；首版轮询即可 |
| `POST /api/workflow-runs/:id/actions` | 暂停、继续、取消；携带预期控制版本 |
| `POST /api/workflow-runs/:id/nodes/:instanceId/actions` | 重试、检查决定、核查未知结果 |
| `POST /api/workflow-runs/:id/derive` | 创建修改后继续的派生运行 |
| `GET /api/workflow-artifacts/:id` | 产物元数据或受控媒体读取 |

创建、重试、检查和派生等命令带幂等请求键；重复键及相同请求返回原结果，重复键不同载荷返回 409。草稿与状态操作采用乐观并发版本，避免双标签页覆盖或重复批准。

服务端是图校验、状态转移、产物访问和调度的唯一权威。首版所有工作流接口限本机，在 LAN 路由门禁明确拒绝，不能仅隐藏菜单。请求体大小、产物读取和导入定义按现有 HTTP 边界补充限制。

导出工作流仅包含版本化定义和非敏感配置，连接采用逻辑名称；导入后重新绑定本机连接与素材。首版导入仅接受已注册节点，不携带可执行代码，不自动运行。图布局可随定义导出，运行产物另行处理。

## 10. 首个内置示例：批量反推并生图

示例节点与绑定：

1. 「原图」输入：`list<image>`。
2. 「反推要求」输入：`text`，可填写用户自己的指令。
3. 「逐图处理」循环：输入原图列表，捕获反推要求。
4. 循环内「构造指令」：模板引用反推要求。
5. 「Grok 反推」：指令来自模板；图片列表由当前项组成；输出文本。
6. 可选「检查提示词」：用户可删掉该节点，并将模型输出直接接到生图。
7. 「生成图片」：提示词来自反推或检查输出；参考图默认当前原图。
8. 「预览」及可选「保存到内容库」。

同一套基础能力必须支持：删除生图节点只保存描述；替换为 ComfyUI；固定另一张参考图；串接翻译模型；同一提示词连接两个生图节点；用 zip 将两组图片逐项配对。

这些变体通过编辑图完成，不增加“反推模式”业务分支。多结果可用多个生图节点；批量张数、种子等只在后端真实支持时展示。

## 11. 仓库实施结构

建议新增区域，文件按职责拆分，避免提前建立庞大插件框架：

```text

src/server/application/workflow/      服务、调度、节点注册、执行与恢复
src/server/data/workflow*.js          仓储、迁移、状态抢占与幂等命令
src/server/assets/workflow*.js        产物存储和安全清理
src/server/http/workflowRoutes.js     API，调用应用服务
src/renderer/src/features/workflow/   列表、画布、配置、运行与批次结果
src/agent/executors/                  必要的受限模型适配改造
test/unit/                           图规则、绑定、状态、失效判定
test/integration/                    API、数据库、执行器替身、恢复与文件
test/ui/                             搭图、检查、批次操作和刷新恢复
```

接线点：`server.js` 组合服务、`routes.js` 与 `lanRoutes.js` 注册权限、`wikiMigrations.js` 追加迁移、`WikiSidebar.jsx` 与应用路由接入页面。

应用层仅通过 `executorsPort.js` 导入 Agent 执行器。共享目录不能依赖 Node、后端或 React Flow。HTTP 层不直接导入数据仓储。聊天与工作流共享媒体保存原语，不互相依赖业务轮次。实施必须通过现有架构检查。

## 13. 验收与验证

### 13.1 用户能力

- 从空白画布搭建反推流程，保存后重新打开，连线和参数一致。
- 删除或添加节点能改变执行方式，不需要修改后端业务代码。
- 一份提示词连接两个生成节点，分别得到结果并保留对应来源。
- 20 张输入图按稳定项 ID 对应 20 组结果；改变完成顺序不改变配对。
- 固定参考图和两组图 zip 配对均能运行；长度不等有明确错误。
- 提示词可人工修改后继续，原始文本仍可查询。

### 13.2 故障与一致性

- 生图失败重试不会重新反推；保存失败重试不会重新生图。
- 模拟请求发送前、发送后、结果落盘后、事务提交后崩溃，分别进入正确恢复路径。
- 外部结果未知不被批量重试；用户明确重新执行保留旧尝试。
- 双击运行、重复检查、重复保存和重复事件不会产生重复逻辑操作。
- 取消后的迟到回调不启动下游；旧尝试不能覆盖新尝试。
- 删除源资料后，已准备运行仍使用快照；删除运行不破坏派生运行和内容库图片。
- 一个循环项失败不阻止其他项；服务级故障暂停对应资源后续请求。
- 修改模板只影响新运行；派生运行正确复用无关结果并使相关下游失效。

### 13.3 权限与资源

- LAN 对定义、运行、事件、动作、产物均被拒绝。
- 伪造路径、跨运行非法产物引用、未知节点、过大图和超量展开被服务端拒绝。
- 凭证不出现在图定义、事件、日志或导出文件。
- Grok 反推步骤企图调用生图或文件工具时，适配器拒绝并给出可诊断结果。
- 大批次使用有界内存，结果表分页，事件按游标读取；多个运行遵守共同并发限制。

### 13.4 执行检查

先运行新增单元、集成与 UI 用例，再运行 `npm.cmd run check`；打包交付前执行 `npm.cmd run package:dir` 并验证新模块资源存在。真实模型验证使用少量样本，明确验证输出、参考图传递和恢复行为；模拟执行器通过不等于模型真实可用或输出质量合格。

不以视觉结果可复现作为验收条件；即使参数相同，外部模型也可能返回不同结果。验收重点是数据绑定、执行次数、状态、来源与恢复正确。

## 14. 发布、恢复与剩余边界

新增模块默认可见但不自动运行；已有聊天、内容库、关系画布行为保持原契约。新增数据库结构采用增量迁移，启用前对真实数据目录做完整备份；失败时关闭模块入口与调度器，保留数据用于诊断。

旧版本程序可能拒绝包含新迁移的数据库，回退必须恢复升级前整套数据库与资产备份，不能只替换程序并假设兼容。工作流目录纳入备份说明。

当前没有必须由用户先回答才能实施的产品阻塞项：图片来源与参考图配对都通过图配置表达。外部执行器能否严格限制工具、查询未知结果、共享资源锁是否需要影响已有聊天，是 W04 的技术验证点；验证失败时停止开放对应节点能力，修订适配方案，不降低执行契约。

本次采用 sr-design-gate 的 Artifact 路线。交付物是设计与实施文档；下一步是按 W01–W10 开发或拆分任务，本次没有执行数据库迁移、调用模型或改动业务代码。
