# 工作流

工作流位于本机侧栏。可以从空白画布组合节点，或复制「批量反推并生图」。执行由后端负责，关闭页面后仍可继续；重新打开后从运行历史查询结果。

## 搭建与运行

1. 新建空白或复制内置示例，给流程命名。
2. 单击节点库条目添加节点，也可拖到画布指定位置；点击画布节点编辑配置。输入直接列出兼容的上游变量和循环内容，选中即建立连线；拖动端口也可连线。
3. 节点库统一使用「元素」入口，在属性中选择文字或图片。元素选择内容来源：固定内容、运行时提供；包含变量时显示「文字与上游结果」；后续处理节点通过连线直接接收上游结果，无需添加中转元素。图片统一选择和排序，无需预先声明单张或多张。文字直接填写；需要引用其他文字时，通过「＋插入上游文字」在当前文字光标处插入来源，无需文字组合或模板节点。模型／生图的提示词使用相同编辑器。数字和开关等程序数据仍可由处理节点传递，旧定义保持兼容。
   循环内可选当前项、序号和带入的外部内容。字段路径、取第几项及拼接分隔文字均有普通表单；列表输入通过添加、移除逐项配置。
4. 文字元素可同时包含固定文字与引用。固定文字节点左侧的「＋接入文字」可直接接收模型的 `text` 等文字输出，连线后会在内容末尾插入引用并打开该节点的配置；文字与变量块按顺序显示，可在变量块前后补充文字，直接选择变量来源或点 × 断开，再将 `value` 连到图片生成的提示词即可。继续接入可追加其他文字来源，已有引用的连线支持断开和改接。运行时提供及资料库素材不展示此追加入口。只有通过连线或插入操作创建的变量块会被解析；直接输入的普通 `{{...}}` 保持原文。模型输出中的 `{{...}}` 不会再次展开。
5. 保存并校验。校验显示按循环 maxItems 估算的调用上限；可以降低该值。保存允许未完成草稿，运行要求完整校验通过。
6. 列表里每条流程可以直接「运行」或「编辑」，也可以打开最近一次运行。新建、导入、复制和归档留在列表或「管理」菜单。进入运行后不显示配置画布。没有运行时内容时直接开始；需要提供内容，或选择首项试跑时，先进入运行工作台：左侧是本次输入和开始按钮，右侧说明将执行的步骤、哪些步骤要人工审核、哪些步骤会写入内容库。窄屏按输入、状态、产物上下排列。只显示来源为「运行时提供」的元素；没给这些输入起用途名时，只显示类型。固定内容无需重复填写。开始后，左侧变成这次已提交的输入快照，再次运行会另开一轮。可通过「返回编辑」调整流程，编辑画布的选择和撤销会保留。文字直接填写或从资料库选择；图片通过素材选择器添加，显示缩略图，可上移和移除，无需填写 ID 或 JSON。运行开始前保存独立快照，派生运行保留未改动固定素材的原快照。服务端拒绝服务器文件路径。
7. 「首项试跑」在编辑工具栏和运行前说明里就与完整运行区分开。试跑先显示涉及的循环，再对每个循环的实际输入列表取首项；固定素材、运行时输入和上游生成的列表均适用。参考图片列表保持完整，其他节点正常执行。没有循环时禁用试跑。试跑限制保存在运行快照中，不修改草稿；试跑内的重新执行仍保持首项限制。zip 的两组输入须长度相等。

循环节点通过「打开循环子图」编辑内部节点，顶部「主流程」返回。将外部素材直接连到循环节点的「＋带入外部内容」端口即可创建入口，类型自动确定；子图按来源名称选择「循环外的内容」使用。「循环返回的结果」在子图未选中节点时配置，主流程不再配置没有消费方的输出映射。首版只支持一层循环。

连线可点击选中后按 Delete／Backspace 或点击工具栏「断开连线」删除；属性中的已连接输入也有独立断开按钮。拖动已连线的端点到空白处可断开，拖到兼容端口可改接。改接到不兼容端口或按 Escape 取消时保留原连线。断开只移除当前依赖，文字中的其他片段保留；等待上游的端口不会自动重新连接。断开和改接均可撤销。

返回列表时保存当前草稿，包括尚未完成的节点配置。调用节点只选择模型适配器，具体模型和调用方式在适配器设置中管理。支持框选、复制粘贴、撤销重做和展示分组。ID 不随显示名称改变。保存草稿后可以导出定义 JSON；导入只接受已注册节点，不自动执行。定义中不允许凭证，连接使用本机设置中的执行器。

画布卡片的默认标题只显示一次：文字、图片、模型调用或图片生成等；自定义名称时才补充节点类别。固定内容与输出类型不重复占行，运行时提供的素材保留对应提示。素材卡显示文字摘要或已选图片数量，处理节点保留连线入口。编辑器和运行快照使用同一套卡片。

## 节点配置

编辑旧草稿时将 input 显示为运行时提供的元素，保留节点和参数标识；保存后采用 element 契约。旧模板与已完整绑定的 concat 配置在编辑时转换为普通文字元素内的片段并保留分隔符，旧执行契约仍可读取；上游中转元素和预览节点只兼容旧定义，不再提供新建入口。编辑草稿移除没有消费方的主流程输出映射，循环返回映射保留。历史运行快照不改写。

检查、保存、列表收集、取列表项和配对操作的类型，以及循环的列表／外部内容类型，从绑定来源自动确定并随上游修改更新，不再重复手动声明；字段提取等确实无法静态确定的输出仍由用户声明。

内置示例只保留两个素材元素和一个循环；循环内部为理解图片、人工确认、生成图片，直接传递提示词和当前图片，不再添加转发模板、单图包装或预览节点。

所有节点的当前契约版本为 1。图结构为 `{schemaVersion:1,nodes,outputs}`。节点包含 `{id,type,version,name,config,inputs,position}`。模型的公开输出变量为 `text`（原始回答）及可选的 `structured_output`（校验后的 JSON）；生图输出为 `images`，其他节点保持 `value`。旧 `value`／`raw` 引用和产物存储仍可读取，不修改历史运行。

### 模型输出与字段引用

画布出口显示「回答原文」「结构化结果」「生成图片」等名称，属性面板同时保留变量标识及类型。选择结构化输出后，可编辑 JSON Schema；其中声明的文字、数字、开关、对象及列表字段会成为可选择的输出变量，例如 `提取信息 / structured_output.title`。文字框的「＋插入上游文字」只列出文字变量，普通输入按所需类型过滤，循环返回也可选择单独字段，无需额外创建字段提取节点。字段连线显示路径，改接目标时保留所选字段；断开和撤销仍适用。

`text` 的含义不随输出格式切换而改变。启用结构化输出时，原始回答先保存，再进行 JSON 解析和 Schema 校验；校验失败保留原文、标记节点失败并阻止下游。运行时不存在的可选字段也会明确报错。当前 Schema 是回答校验契约，适配器尚未声明模型原生结构化生成能力，提示词仍需要求模型返回符合结构的 JSON。

这版借鉴 Dify 的具名、带类型的节点输出和字段选择，保留本项目以绑定推导执行依赖的调度方式。Dify 的执行连线与变量引用相互区分，不能把本项目的数据连线称为完整复刻其执行图。模型及调用协议继续由适配器负责。

参考：[Dify 变量概念](https://docs.dify.ai/en/learn/key-concepts)、[LLM 结构化输出](https://docs.dify.ai/en/cloud/use-dify/nodes/llm)、[执行编排](https://docs.dify.ai/en/cloud/use-dify/build/orchestrate-node)。

| 节点 | 配置与输入 |
| --- | --- |
| element | `valueType`、`source:"fixed"/"runtime"/"upstream"`；固定及运行时内容使用 `parameter`、`default`，上游来源仅兼容旧定义并使用 value 输入。文字可保存 `parts:[{kind:"text",text},{kind:"ref",ref:绑定}]`，运行时计算，引用自动成为图依赖；这类文字不作为运行输入参数。文字及图片可用 `{elementId}` 选择资料库素材，在运行准备阶段固定快照 |
| input（旧定义兼容） | `parameter`、`valueType`、`required`、`default`、`allowEmpty`；运行参数作为输出 |
| template（旧定义兼容） | `parts` 数组：`{kind:"text",text}` 或 `{kind:"ref",ref:绑定}` |
| model | `adapterId` 保存适配器 ID；`outputType` 选择适配器支持的输出格式；输入契约由适配器提供 |
| image.generate | `adapterId` 保存适配器 ID；`parameters` 为适配器声明的任务选项，`adapterConfig` 为适配器自有任务配置；输出图片列表 |
| transform | `operation` 为 field、concat、list、nth、zip、successes；`valueType` 声明输出类型 |
| foreach | `itemsType`、`maxItems`、`captureTypes`、`body:{nodes,outputs}`；输入 items 和捕获端口 |
| review | `valueType` 为 text 或 list&lt;image&gt;；输入 value |
| preview（旧定义兼容） | `valueType`；输入 value，不保存到内容库 |
| library.save | `valueType` 为 text、image 或 list&lt;image&gt;，`tags`、`source`；输入 value，输出元素 ID 列表 |

transform 的 field 使用 `path:["字段",0]`，输入 value 为 json；nth 使用从 0 起的 `index`；concat 使用 `keys:["a","b"]`、`separator`；list 使用 `keys` 声明逐个输入；zip 使用 `listType` 和可选 `otherListType`，输出 `list<json>` 的 `{a,b}` 列表；successes 只保留循环结果的成功项。json 与 text 不隐式互转。接收图片列表的端口可直接接收单图，执行时包装为单项列表，无需额外创建列表节点；执行契约仍兼容单图和列表，编辑旧草稿时将图片素材规范为列表，历史运行快照不变。收集图片时按输入顺序合并各组图片。循环汇总行的 outputs 保存 `{artifactRef,type,path}`，避免一次载入所有长文本；field 取到这种引用时读取对应产物，再检查声明的输出类型。

文字输入端口也可保存 `{kind:"text",parts:[...]}`，支持直接在模型提示词中组合固定文字和引用。引用只允许文字来源，并参与类型检查、循环检测和派生失效。删除引用连线同步移除该文字中的引用。同名来源通过独立标记区分。带引用的固定文字由执行器计算；运行时整段手动提供与计算引用互斥，移除引用后可切换。循环内可添加文字元素，引用当前文字项及带入的文字。

提示词直接接入上游后，也使用相同的文字与变量块编辑器，不需要切换到「补充文字」。参考图片直接选择来源即连线，可断开或选择不使用；循环面板的「＋带入内容」与画布「＋带入外部内容」建立相同的捕获绑定。

模型适配器边界：服务端注册入口为 `src/server/application/modelAdapters/index.js`，前端配置入口为 `src/renderer/src/features/modelAdapters/ModelAdapterFields.jsx`。工作流通过目录获取适配器的输入、输出、任务选项和配置界面，不导入具体后端实现。适配器负责输入契约、参数校验、执行配置快照、调用、资源标识、失败分类及安全取回；工作流仅负责连线、调度、产物持久化和检查。模型名称、CLI/API、服务地址和后端字段映射不由工作流解释。

`GET /api/workflow-node-types` 返回 `adapters` 目录，配置操作通过 `/api/workflows/adapters/:id/:operation` 转发，由适配器声明允许的 HTTP 方法，全部仅限本机。ComfyUI 的旧配置接口由适配器声明的兼容路由继续提供。`config.adapterInputs` 是适配器生成的输入契约提示，服务端在保存、运行以及读取历史执行节点时重新从适配器确定，不信任客户端伪造的类型。运行快照保存适配器生成的配置，修改软件设置不会改变原任务的安全取回配置。

兼容旧的 `config.comfyui` 和原适配器 ID，读取时由对应适配器转换，不改写历史运行记录。旧文字节点中的模型、effort 覆盖只在适配器兼容层读取，新界面不再提供这些控件；新节点使用 `adapterId` 并只接受目录中声明的任务参数，拒绝模型覆盖，默认使用适配器设置。旧 `executor` 字段仅作为适配器 ID 的兼容别名。适配器暂不可用时草稿仍可打开并重新选择，运行会明确报告不可用。新增适配器无需在工作流调度、服务、输入契约或运行界面中添加后端分支。

Grok 生图只开放 `parameters.aspectRatio`，不会忽略不支持的参数。文字调用使用独立上下文，在适配层拒绝所有工具。模型 JSON 输出始终经过 JSON 解析，可额外设置 `jsonSchema`；支持 type、properties、required、items、enum、additionalProperties、description，其他关键字报错。失败时保留原始回答。

ComfyUI 连接地址沿用设置。该适配器自有的 `config.adapterConfig` 可保存 API 图 `workflow`、提示词映射 `prompt:{nodeId,input}`、输出映射 `outputNodeId`、可选 `workflowName`。生图节点选择 ComfyUI 后，只能读取 ComfyUI 中已保存的工作流，不提供 JSON 导入。工作流的创建、编辑和保存由 ComfyUI 负责；Wiki 仅保存调用快照、参数与映射，不回写远端工作流。选择工作流不会提交生成任务，也不会创建画布连线。只有一个候选的输出、提示词字段或图片入口会自动填写；多个候选时保留为空并要求选择。提示词来源可选沿用原工作流（不改任何文本字段），或用本节点内容替换显式选中的 `nodeId/input` 字段。只执行选定输出的依赖。参考图通过 `imageInputs:[{nodeId,input:"image"}]` 按列表顺序映射到不同的 LoadImage，最多 8 张；传图时数量须与映射一致，未传图时保留原工作流图片。重复入口、不可达入口和数量不符在提交前报错，未映射字段不变。旧定义未声明 imageInputs 时仍兼容唯一 LoadImage 的单图规则。服务未配置时校验会明确报错。首版不注册 ChatGPT 网页版或 Codex 原生生图。

ComfyUI 工作流生图最多接收 16 张图片。导入图有数值 `batch_size` 参数时，「调整本次生图参数」和结果页「调整参数」会在常用参数中显示「生成数量」；设置为 N 张会顺序提交 N 次单张请求，每次实际 `batch_size=1`，不会在同一个 latent batch 中生成多张。随机种子每次重新取值，固定种子保持原值，可能得到相同图片；参考图只上传一次。数量和其他临时参数一起冻结到新运行，不修改流程默认值。多个数值 `batch_size` 中大于 1 的数量须一致。没有该参数的图仍按其实际输出返回图片，不会自动插入批量节点。所有图片按请求与远端输出顺序保存，形成一个 `list<image>` 交给下游；人工确认可逐张选择保留。记录每次请求的任务 ID，取消后不再提交后续请求。全部请求生成完成后再下载结果，任意一张下载失败都不会发布部分列表，可按原任务 ID 集合重新取回全部结果，恢复不会重新提交生图。若生成中途失败、仍有请求未提交，不会把已完成的部分当作全部成功，须核对后明确重新运行。历史单任务结果仍可按原任务 ID 取回。对话生图入口仍沿用单图返回契约。

## 检查、故障与继续

编辑草稿和查看运行分开，运行图与参数不会被草稿修改。运行页先显示需要处理的审核、失败恢复和「节点产物」；这里的产物是各节点的结果，不是单独声明的最终输出。接受审核只继续该分支，本身不会写入内容库；只有执行到保存节点才会入库。审核通过后仍可查看该次产物。运行记录页默认显示可编辑内容，不再提供逐节点的“编辑/编辑中”按钮；文字、图片和生图参数可以一次修改多个节点，编辑和参数弹窗确认都不会提交任务。统一运行栏显示改动数和执行范围，只有点击“运行”才另建运行记录：未修改或修改后恢复原值时，按本次快照的配置和输入完整执行；修改节点时，执行这些节点及受影响的后续节点，复用其他可用的已完成结果。受影响的审核必须重新通过才会保存。运行次数每次打开或切换运行页面、提交后均默认回到 1，只对当次提交生效，不随工作流保存，也不沿用旧定义中的次数。仍支持当次选择 1–20 次，一次提交按相同范围创建相应数量的独立运行，重复请求不会重复创建。节点、循环项和整批结果不再各自提供重跑或重新生成入口；错误恢复和人工审核仍在原处处理。尝试记录、增量事件、版本派生、运行快照和定义 JSON 在「执行详情」里。每个节点可通过「查看最近运行结果」查看上次执行的内容；这不会执行新调用，也不包含尚未运行的草稿修改。无需创建预览节点。循环子节点只在批次表中展示；完整实例分页放在折叠诊断区，主流程节点不受诊断分页影响。节点高级设置保留完整配置 JSON，正常操作无需填写具体模型或执行方式；ComfyUI 工作流和映射由适配器提供普通表单；节点结果优先显示名称及内容，内部标识与哈希留在来源和诊断信息中。

ComfyUI 配置中的「工作流参数」根据服务返回的节点定义生成数字、选项、开关或文本控件，可调整所选输出依赖中的尺寸、种子、步数、CFG、采样器、模型等实际存在的参数。提示词替换字段和 LoadImage 图片入口单独配置，已连接的字段不作为普通参数。数字离开输入框时生效，无效或超范围的数字恢复原值。修改直接保存到当前节点的 API 图副本，不改远端已保存的工作流；重新打开节点会重新读取控件定义并保留已保存参数和映射。

循环表每页 20 项，保持输入顺序和稳定项 ID。各项独立执行，失败不终止其他项。节点列表每页 100 个实例，事件按游标增量读取。人工检查可接受、修改文字后接受、选择图片子集后接受、拒绝，或明确选中多个检查后批量接受。原文与修改后的产物均保留。

暂停停止调度新的节点，已开始的节点可完成；取消尽力停止在途请求。取消后的迟到结果仅归档到原尝试，不会执行下游或保存内容库。

外部调用不自动重试。确认失败后可重试单个节点，复用成功上游；内容库保存失败只重试保存。结果未知时，不能按普通失败重试：可以核查远端后明确重新执行，或放弃。ComfyUI 已记录确认任务 ID 时可以「核查并取回」，此操作只查询原任务。Grok 暂不提供安全远端取回。

重启会恢复队列、检查等待和本地计算；已经记录提交意图的外部调用归为未知，不会自动再次提交。每次实际执行追加尝试记录，旧尝试不能覆盖当前输出。

修改配置后使用「用当前草稿派生运行」，也可以从成功节点发起「派生运行：重新执行此节点及下游」。默认复用严格快照匹配的成功结果，受影响的依赖闭包重新执行。展示名称与坐标不影响复用。首版派生以主图节点为失效单元：循环内部修改会使整个循环失效。循环汇总已被下游消费后，重试内部失败项须改用派生运行，保留已消费的历史结果。

运行页的主流程 AI 步骤提供「复用已有结果，不重新调用」开关。开启后，派生运行直接沿用当前记录中该步骤的成功产物，即使上游输入有变化也不重新调用，并显示来源运行编号；步骤自己的配置须保持不变。没有成功结果时禁用开关，产物缺失或损坏时停止派生并提示，不回退到模型调用。人工确认与保存重新执行。此选择仅作用于本次派生，不修改流程草稿，也不会自动搜索其他历史运行。API 使用 `reuse: [nodeId]` 指定主流程 AI 节点，事件记录显式复用列表。

状态仅显示指示灯：成功绿色、失败红色、运行中蓝色缓慢闪动、等待确认或状态未知黄色、未运行或跳过灰色。状态说明放在悬停提示和无障碍标签中，不常驻显示；系统启用减少动态效果时关闭闪动。

Grok 1.0.70 的纯文字会话不能使用空的 curated tool registry，否则 `session/new` 返回 `Internal error`。文字适配器注册一个已知的 `read_file` 条目后通过 `disallowedTools` 排除，保持禁止默认工具、文件和终端权限、其他 MCP 与技能发现；发送前核验持久化的注册表和排除规则，完成后再次核验模型实际工具定义为空。配置初始化错误会保留可诊断的配置原因，不输出任意 RPC 数据或 CLI stderr。

## 存储与边界

- SQLite 迁移 40 新增工作流、版本、运行、实例、尝试、产物、引用、事件、保存回执和幂等命令；不改写已有聊天或资料内容。
- 全局外部请求上限为 10；Grok 同时最多 10 个，每个 ComfyUI 服务仍为 1。聊天与工作流共用适配器资源锁。
- 每作用域最多 100 节点，总定义 300 节点，循环最多 1000 项，总展开上界 20000 实例。循环每次最多保持 10 个未完成输入项，这些项里的 Grok 步骤一起执行，文件按需读入。
- 所有工作流 API，包括定义、运行、事件、动作和媒体，均拒绝 LAN；请求定义／运行体最多 1 MiB。
- 图片固定在 `data/workflow-artifacts/`，尝试目录位于 `data/workflow-workspace/`。内容哈希与大小会在取回时核验。
- 归档不删除历史；首版不自动清理运行产物。已保存到内容库的图片有独立存储与保存回执。

升级前请停止应用并完整备份实际 data 目录。程序同时会在迁移前保存数据库快照到 data/backups，但这不替代资产备份。回退旧程序应恢复整套升级前数据。工作流两个目录也应纳入后续备份。

## 粘贴与上传图片

工作流中的粘贴、上传使用本机专用接口 `/api/workflow-input-images`，返回 `{ attachmentId }`，不创建内容库元素。附件记录保存在 `data/workflow-input-images/`，图片文件沿用 `data/workflow-artifacts/` 的哈希存储；二者都需要纳入备份。附件随草稿保留，当前不自动清理，以免破坏已保存草稿。

开始运行时，附件经文件大小、哈希核验后转换为独立的运行产物引用。运行与派生继续使用运行快照；选择现有内容库图片仍沿用 `{ elementId }`。只有显式执行 `library.save` 才会将附件或生成结果写入内容库。旧版本误入库的粘贴图片没有可靠的专属来源标记，本次修复不自动删除或迁移既有库条目。
