# Wiki 会话第一版

2026-09-09 权限更新：局域网共享现与本机拥有相同的应用权限，开放会话、会话关联及中间图片、编辑、回收站、整理配置和语义检索。仍无需登录，保留局域网地址及同源校验。下文原有 LAN 只读或私有内容隔离描述为历史设计，以本更新和 README 的局域网共享说明为准。

日期：2026-09-08。用户已同意 assistant-ui、Codex app-server、Wiki CLI 的组合并授权实施。

## 范围

本机 Wiki Agent 主工作区与按需打开的侧边会话面板：持久会话和消息、流式回答、停止生成、重启后续聊、选择文字/图片资料、可点击来源、生成文字及标签/关联建议、采纳/拒绝/条件撤销。沿用自动整理设置中的 Codex 程序、认证目录及模型。聊天的整轮时限已按下方“长时间创作与无进展提示”修订移除。LAN 仍只读且不开放会话。

## 实现边界

- Node 会话服务通过 stdio 管理 app-server；不解析终端界面。使用安装版本生成的协议核对请求。app-server 的客户端工具调用属于实验接口，须明确启用并测试；继承用户已配置的 MCP。
- 模型通过 `wiki_cli` 客户端工具传递 argv 和 stdin，服务用真实 Node 子进程执行现有 Wiki CLI。该工具提供内容检索及 `chat propose`；聊天同时开放 Codex 创作工具，详见下方能力修订。
- CLI 仍经 HTTP 使用 Wiki；模型不能运行采纳/删除/直接写内容命令。`chat propose` 使用短期运行令牌，服务验证其所属会话、读取过的内容、当前运行状态。一般 UI 不持有此令牌。
- Wiki 持久保存消息、资料快照、Codex thread ID、建议与实际变更。Codex 历史负责模型上下文；Wiki 记录负责界面和内容来源。不同会话可以并发生成，每个会话同一时刻一轮，限制资料数、工具次数和输出；长时间未收到进展仅提示等待，不设整轮截止时间。

- 文本与图片都可加入资料；图片通过 Wiki 缩略图传给模型。用户附上的资料展示在用户消息中，助手回复不再单独展示“本轮参考资料”列表。检索命中仅算候选，实际读取的资料仍保存为来源记录，供正文引用和保存内容关联使用。保存新文字可附来源关联；正文覆盖留到后续版本。
- 建议采纳与实际内容增量写入在同一个短事务中完成，重复采纳返回原结果。新增文字、标签、关联仅记录本次实际新增项。撤销前比对依赖版本；不覆盖后续修改。模型、CLI、图片读取和网络均在事务外。
- 浏览器断开不取消任务，重开面板读取持久记录；停止会中断 Codex 并取消在途 CLI。后端退出停止子进程；重启将未完成消息标为中断，允许继续同一 Codex 会话。不自动重发不确定的一轮。

多会话并发采用 `sr-design-gate` Inline 路径：服务按会话保存运行状态与 Codex 连接，每个会话使用独立进程和 `chat-workspace/<sessionId>` 工作目录，连接空闲 60 秒后回收，后续通过已保存的 thread ID 继续。通知按连接所属会话及 thread/turn ID 校验；工具凭据、图片、用量、停止及异常清理均归属对应会话。数据库 `begin` 在既有短事务内只检查当前会话，不新增表或迁移。会话详情和 SSE 返回当前会话的 `running`，状态接口返回 `activeSessionIds`；前端不再因其他会话生成而禁用输入。

检测连接使用独立的元数据连接，运行中的会话继续生成并在下一轮重载配置。应用退出停止全部会话并回收全部连接。图片提示词后台整理仍逐个执行，挑选时跳过正在生成的会话；它可以与其他会话的用户消息并发。验证覆盖同时生成文本、图片与工具建议、同会话防重、独立停止和强制终止、启动失败、进程崩溃及重启恢复。

2026-09-10 并发验证：相关后端回归 66 项（1 项随机端口被禁用，单独复测通过），新增空闲进程回收及后台队列测试均通过，最终聊天界面 26 项全部通过，构建及架构检查通过。并发专项同时使用不同模型和努力等级，并验证图片、建议及流式结果归属；模型调用使用 CLI 协议模拟进程，未发起真实推理。日志保存在 `.local/concurrent-chat-*.log`。运行中的应用需要重启以加载后端改动。

## 生成图片继续编辑（2026-09-08）

## 创作输入与 Wiki 管理的边界（2026-09-09）

用户明确：Wiki 保存内容并管理内容之间的关系，管理信息不能自动成为生图或写作的依据。采用 sr-design-gate Inline 路径，不增加意图分类模型或任务模式字段。

- 普通请求保留用户原话，所选文字只提供正文，所选图片提供图像、文件名和附件序号。`chatReference` 明确选择允许进入模型输入的内容字段；完整来源快照继续用于界面、来源记录、删除清理和修改冲突检查。
- 普通会话不再常驻 Wiki Agent 角色、标签/关系/提取操作规则，也不追加最近建议状态。`wiki_cli` 保留简短能力入口，调用 `schema` 时再返回管理规则与建议状态；用户触发的提取和图片归档任务单独加载管理说明。自动整理和图片检索描述任务各自使用原有任务输入。
- 历史恢复只提供用户引用的材料、成功读取工具的正文/图片、对话和生成结果。搜索候选、来源快照的管理字段不自动变成参考材料。图片编辑历史通过附件序号和选区保留原图指向。
- 请求记录标记 `contextFormat: content-only`。旧格式的模型会话在下一次发送时重建，此后恢复正常续接，不删除原消息或改写旧调用记录；不需要数据库迁移。

验证在模拟 app-server 实际收到的请求上检查文字、图片、顺序及元数据排除，覆盖普通续聊、按需读取管理说明、旧上下文重建、分支和历史图片编辑。验证不等同于真实图像模型的出图质量评估。

## 内置文件工具（2026-09-10）

采用 sr-design-gate Inline 路径。针对 Shell 调用依赖本机 `rg` 等程序的问题，为会话增加 `list_files`、`read_file`、`search_files` 三个动态工具，由服务端使用 Node 标准库直接执行。开发者指令优先使用这些工具处理当前会话目录内的文件；目录外的技能说明和图像内容仍使用原有原生工具。文件内容按数据处理，不作为用户或开发者指令。

工具只读当前会话工作目录，校验词法路径及真实路径，拒绝越界读取；递归遍历跳过符号链接和特殊文件。列举与搜索支持相对路径、绝对路径、递归开关及 POSIX glob，省略 glob 时包含隐藏文件。搜索使用字面文本，返回文件路径、行号和片段。文本读取支持 UTF-8 和带 BOM 的 UTF-16，按 JavaScript 字符偏移分段；拒绝二进制和超过 1 MiB 的文件。

单次遍历最多检查 10,000 个条目、32 层目录，搜索读取预算 8 MiB，最多返回 200 项；结果和跳过记录有输出长度限制，未完成的扫描明确返回 `truncated` 与 `skipped`。文件句柄在完成、失败和取消时关闭，当前会话停止信号传入执行器。工具调用沿用现有次数预算、参数/结果记录及 SSE，过滤 CLI 对同一动态工具的重复通知。命令执行失败但已返回 `aggregatedOutput` 时，直接展示实际错误输出，避免误报“未返回具体原因”。

工具通过 [Codex app-server 动态工具协议](https://learn.chatgpt.com/docs/app-server) 注册；本机 0.153.1 生成的实验协议 schema 只在 `thread/start` 接收 `dynamicTools`，`thread/resume` 不接收。请求记录增加 `toolsetVersion: 1`，旧会话下次发送时使用已保存历史新建模型上下文并注册工具，此后正常续接。历史仅作为数据重放，不重新执行工具；无需数据库迁移。glob 使用 [Node 的 path.matchesGlob](https://nodejs.org/api/path.html#pathmatchesglobpath-pattern)，实际验证运行时为 Node 24.16.0，无新增依赖。
