# 对话请求快照与工具详情

每轮进度栏的“查看本轮请求”默认折叠。工具详情对应每个调用，连续操作合并展示时仍分别记录。每项工具的“查看详情”也默认折叠，即使工具正在运行或失败，也只展示状态和错误原因；手动展开详情后才按需请求记录，不把大段参数和输出重复放进会话 SSE 快照。

## 记录边界

- 应用请求：在调用 `thread/start` / `thread/resume`、`turn/start` 前，保存同一参数对象的文本快照。包含用户原话、应用指令、实际补入的资料和历史、模型、努力等级以及附件顺序。确认响应和响应失败分别标记，超时/错误不能据此断言请求未执行。
- 续接会话：明确这是新增请求，CLI 内部保留的上下文和内部指令不属于本应用完整可见的范围。
- 工具：保存 CLI 开始/完成事件中实际提供的参数及结果。图片 `prompt`、`revisedPrompt` 分别展示；只有二者均有完整记录时提供区段对比。CLI 未返回的字段不补造。Wiki CLI 另记录实际程序、参数、stdin、退出码、stdout/stderr 及回传给模型的内容，不记录进程环境。
- 图像等二进制内容保存类型、字节数和 SHA-256，保留附件数组顺序，不把 Base64 展开到界面。正文类字段最多保存 512 Ki 字符，每条记录文本预算为 2 Mi 字符，数组最多 1000 项，嵌套深度最多 16。超限、二进制省略和已识别的凭据字段隐藏均附带说明。
- 历史请求没有快照时返回未记录；旧工具事件里已有的参数可以查看，并标为历史部分记录。

## 存储和接口

Wiki schema 21 新增 `chat_trace_records`，以 `(turn_id, record_key)` 为主键。`request` 对应本轮请求，`tool:<事件编号>` 对应单次工具调用。记录有独立版本和来源/历史依赖，会话快照仅带版本号用于刷新已展开的详情。

`GET /api/chat/turns/:turnId/trace` 返回请求记录；附加 `?event=<事件编号>` 返回对应工具记录。接口沿用会话可见版本检查，不暴露内部整理轮次；记录以普通文本渲染，支持复制，不执行其中的 HTML、脚本或命令。

创建分支时复制已有记录，保留原始请求里的标识，并将清理依赖映射到分支内的历史轮次。修改资料不重建旧快照。彻底删除会话、来源或被依赖的历史内容时清空相关记录，保留已清理状态；迟到的回复不能覆盖清理标记。

验证覆盖真实 RPC 参数一致性、工具参数和输出、字段缺失、长度限制、复制、桌面/窄屏布局、重启、分支、来源更新、删除清理，以及响应失败的未知接收状态。界面截图位于 `.local/chat-trace-desktop.png` 和 `.local/chat-trace-mobile.png`。
