# Agent 工作台

进入已启用的工作台后，后台并行读取各引擎的模型列表；当前页面内按引擎缓存，新会话和已有会话共用，切换不重复探测。读取期间仍可编辑任务和切换引擎；失败只在对应模型菜单提示，可点击“重试读取模型”。检测不自动发起账号登录，显式连接 Antigravity 账号成功后更新其缓存。

## Antigravity

工作台模型菜单中可切换到 **Antigravity**，使用 Google 官方 ACP 1.4.5。Windows x64 在仓库目录运行 `node tools/install-antigravity-acp.mjs` 安装；安装器下载官方文件并验证固定 SHA256，不会覆盖已有安装。其他安装位置可通过 `ANTIGRAVITY_ACP_EXECUTABLE` 指定服务端可执行文件的绝对路径。开发目录安装在 `.local/antigravity-acp/runtime`；打包部署时应把运行时安装到外部目录，再设置此环境变量。

模型检测优先使用 ACP 已有凭据，不自动登录。模型菜单仅在检测返回需要认证时显示“连接 Antigravity 账号”，点击后在浏览器完成个人 Google 账号授权；已有登录可用时隐藏入口。连接失败只在该模型菜单内提示，其他读取失败可点击“重试读取模型”。桌面版登录不一定被 ACP 共享；授权成功后不必每轮重登。连接账号操作不发送模型任务。

Antigravity 支持文本、参考图、模型和低/中/高推理强度选择（以账号和模型实际可用范围为准）、流式回复、计划、原生工具审批、停止与原上下文恢复。启动前须确认信任原生文件访问及已有配置；手动审批采用服务端 `default` 模式，只返回允许一次或拒绝，不创建长期允许规则。它使用当前用户权限以及 Antigravity 自己的配置、插件、MCP 和工具，工作目录不是操作系统沙箱。原生工具返回的文件差异只供查看，没有完整修改前记录时不提供撤销。

此引擎当前不注入工作台 Wiki/付费任务工具，也不用于受限工作流。服务端不可用、认证失效、模型不可用或恢复失败时明确报错，不会静默换模型、新建替代上下文或自动重发。

2026-10-31 本机验证：官方初始化、Google AI Pro 授权、后续进程复用登录、Gemini 3.8 Flash 两轮真实对话与关闭后上下文恢复通过；原生 `create_file` 允许一次后实际写入成功，拒绝后目标文件未创建。协议 fixture 及界面测试另行覆盖取消、图片输入、断连和状态转换；不能把这些 fixture 结果视为所有原生工具均已真实验证。该服务端实测可能为审批和实际执行返回不同工具 ID，审批占位行的最终状态也可能与实际执行不同；工作台不据此虚构文件已修改，完整差异以实际返回的内容和工作区检测为准。

## Grok 与 Codex

从侧栏打开“Agent 工作台”，首次点击“启用工作台”。开关默认关闭，不会转移或改写旧对话。Grok 不按程序版本号限制发送任务；启动时仍核验工具配置和应用工具通道，文件与命令执行仍经过工作台权限检查。

工作台通过进程专属的 `GROK_AGENT` 显式选择所传入的 Agent 配置，避免模型默认配置覆盖它。会话文件包含完整 `agent_profile` 时逐项核验；仅保存 `agent_name` 时核对显式选择的配置名称。应用工具目录兼容不返回 `sessionMcpResolved` 的 Grok，仍拒绝明确未就绪的目录、其他 MCP 和未完成的应用工具握手。

新建会话时从输入框旁的项目菜单选择已有项目、新建项目，或选择“不在项目中工作”。项目有名称和本机源文件夹，同一文件夹只保留一个项目；之后在该项目里新建会话会沿用它，不再重复确认信任。不在项目中工作时，发送后直接创建独立临时目录和会话，不再弹出工作区信任确认。Codex 和 Antigravity 的原生访问权限说明显示在输入框下方，点击发送即确认使用所说明的原生访问能力；具体操作继续按会话权限审批。会话固定项目与工具范围。模型和推理强度可以在对话里更换，从下一轮开始生效；正在执行的这一轮仍使用打开时的模型和强度。全局配置变化不会改写已有会话。

同项目及父子目录下的不同会话可以并行执行，不再按目录排队；同一会话仍只允许一个活动轮次，外部执行器的并发限额继续生效。各会话共享实际文件和 Git 状态，工作区检测也可能包含其他会话的修改。当前尚未提供自动创建 Git worktree 的入口。

进入工作台即可在中间的输入框描述任务。左侧“项目”按项目列出其中的会话，超过五条时用“展开显示”；“最近”按时间列出全部会话。点项目名展开或收起，并把下一次“新建会话”放进该项目。会话标题取自首条任务，创建后发送失败时，文字保留在该会话的草稿中，手动重试沿用同一个会话。中间对话独立滚动，底部输入框保持可见，并显示当前项目和“此计算机”。Enter 发送、Shift+Enter 换行；执行期间可以先编辑下一条草稿，当前任务结束后手动发送，也可以点击“停止”。

工具与文件操作按原顺序归入默认折叠的“执行过程”，错误和文件、命令审批直接显示在对话中。参考图显示在对应的用户消息中；独立任务审批、任务状态、Wiki 建议和生成结果显示在发起它们的轮次中。上传参考图不会另列为生成结果。右上角“会话设置”切换权限与恢复面板。窄屏下详情面板排在对话下方，可以收起以扩大对话区域。

有文件修改时，执行中显示“X 个文件已更改”，展开可选中文件查看差异。轮次结束后显示“已编辑 X 个文件”摘要，默认展示三个文件，支持展开全部、查看带行号与红绿标记的差异。文件网关的同一文件多次写入合并为本轮最初版本到最终版本的净变化；Codex 使用最新的本轮聚合差异，重复通知不累加统计。过大或不完整的差异明确显示统计不可用。工作区检测到的变化单独展示，可能包含原有修改、命令和外部编辑，不算作 Agent 的文件修改数量。

“撤销 X 个文件”仅恢复具备完整连续版本记录的文件网关修改：恢复本轮修改前的实际内容，新建文件则删除；保留已有未提交修改，不更改 Git 索引，不回退聊天或命令的其他副作用。撤销前检查整批文件，随后在每次恢复前再次核对当前内容哈希；后续编辑发生冲突时停止并保留文件。撤销期间本会话不能发送或恢复，其他会话可继续执行；进度写入 `agent-changes/<turnId>.json`，意外中断后可继续；已撤销的重复请求不再操作文件。结果未确认的轮次不提供撤销。Codex 原生差异目前只供查看，缺少完整修改前版本时不提供撤销。

文件修改卡显示路径和前后文本；命令卡显示实际程序、参数、工作目录与生效环境。允许一次或拒绝均只作用于当前操作。文件、命令和引擎权限审批不限时等待处理；停止任务、关闭应用或后端重启后失效，不会自动批准或重发。等待审批期间暂停 Grok 和 Codex 的轮次超时计时。审批期间文件被其他程序修改时，写入会冲突，不覆盖新内容。命令使用当前用户权限；工作目录不是操作系统沙箱，已批准的命令可能访问目录外文件。

输入框工具栏提供统一的“审批模式”。新建会话沿用这台电脑上一次为 Grok 选择的模式，没有记录时使用手动审批；已有会话保持自己保存的模式，切换引擎后再回到 Grok 也会沿用上次的选择。Grok 支持三个模式：手动审批在实际文件写入或命令执行前确认一次；自动审批交给 Grok 的 Auto 分类器判断，Grok 仍要求用户确认时由工作台展示一次；全部允许自动执行已开放范围内的文件修改和命令。无需分别配置 Grok 与工作台。Codex 当前保留原生手动审批，不提供其他模式。

会话权限中可以增加只读目录，文件写入与命令统一采用上述审批模式。旧版“允许工作区写入”授权在切换审批模式时重置。审批模式与目录权限一起持久化，修改前先停止轮次，保存后下一轮及恢复上下文时采用新策略；旧审批随策略版本变化失效。自动放行记录保存到会话事件中。引擎未确认相应模式时不发送任务。受限会话、受保护路径、工具范围及付费任务的独立审批继续生效。命令使用当前用户权限，文件网关的路径限制不构成命令沙箱。Git 差异包含外部改动，不提供整轮磁盘撤销，也不更新索引。

任务内容和参考图自动保存为本地草稿，按会话隔离；另一窗口已改动草稿时显示冲突并保留当前文字。发送前先保存，使用同一请求标识提交；响应丢失后再次提交不会另开一轮。未保存成功的草稿会触发离开页面保护。

Wiki 工具只读取和提出建议。点击“采纳建议”才写入 Wiki；原内容版本已经变化时拒绝采纳，需要重新读取和提出建议。

图片工具先创建待批准任务，卡片展示执行器、提示词、参考图和有效期。点击“批准并执行”后才派发，可能消耗账号额度或产生费用；目前上游不提供费用预估。原对话结束、界面关闭不会取消已批准的独立任务。不要批准内容相同的新操作来代替查询已有任务。

图片成功后先存入不可变产物库，并显示在对应轮次中；点击图片可查看原图，可以下载、“带结果继续”或显式“保存到 Wiki”。带结果继续只加入下一轮的参考图，不会自动调用模型。上传参考图也不会自动保存到 Wiki。模型看到的是限尺寸预览，下载保留原始产物。

“停止”撤销本轮尚未决定的审批和未批准的图片操作；已批准的图片任务需要单独取消。无法证明远端停止或完成时保留“结果待核查”。“核查并取回”只读取已有结果，不再次生成；“申请重新执行”创建新的待批准尝试，可能再次计费。

刷新恢复已有消息、审批、任务和草稿。重启后已经尝试发送但未确认的轮次、已派发但未确认的任务标为待核查，不自动重发。“检查并恢复原上下文”只加载原会话；失败不会静默新建上下文。无引用产物启动时只报告，查看 `/api/agent/storage-inspection`，不会自动删除未知文件。

工作台仅限已配对的本机用户，LAN 和分享访问者不能调用。应用工具经当前 Grok 连接的 SDK 通道执行，不携带本机管理 Bearer；检测到其他已启用 MCP 时拒绝发送任务。完整实施和验收状态见 [进度](agent-workbench-progress.md)，Codex、工作流桥接和旧聊天转接见下文。

## Codex

新建会话选择 Codex，检测本机模型并确认原生全盘读取。本机已验证版本为 0.159.0；安全读取可能自动执行，写入和危险命令使用原生审批，只允许本次或拒绝。界面显示实际命令和文件差异，缺少可靠关联时拒绝执行。Codex 的读取边界与 Grok 文件网关不同，不提供 Grok 的额外只读目录设置。版本、工具策略或项目身份变化时不能静默移用上下文。

## 工作流

让 Agent 读取可用工作流并提交，会先出现待批准工作流卡，展示名称、固定版本、步骤和 AI 调用上限。批准后通过原工作流服务运行；“打开原工作流运行”可处理人工检查。后续修改草稿或全局执行器配置不会改变已冻结的运行。

完成时保存有限文字摘要与图片引用；完整结果留在原运行。文字和图片均可下载、引用或显式保存到 Wiki。取回只核对绑定的原运行，不重新提交。失败或取消后重新执行仍须批准。

工作流画布新增“受限 Agent”，目前仅 Grok。可勾选允许的应用工具、选择文字或结构化输出；无 Shell、项目文件或管理权限，使用独立上下文。Wiki 建议不会自动采纳，图片和子工作流仍须用户批准。工作流调用深度最多 2，同一祖先工作流不能再次调用。同引擎任务反复查询达到上限会结束父轮次释放资源；点击带结果继续时再发送新轮次。

## 旧聊天与恢复

开关关闭时保持旧聊天行为。开启后，“新建对话”使用新内核 Wiki 模板；在旧聊天发送继续内容时先创建关联的新工作台会话，把文字和当前附件保存为草稿，不自动发送。界面标明上下文转换，提供返回旧会话链接。转换使用新的 Grok 原生会话，不冒充恢复旧 Codex/Grok 线程；最近最多 20 轮有限摘录仅在第一次发送时提供。

旧记录、分支、附件、trace、引用和草稿留在原表，转换不会删除或改写；当前附件按权限复制到新产物库。重复转换同一分支和草稿返回同一新会话，保留新会话中后续编辑。历史中的全部图片和完整 trace 继续在旧会话查看。旧 API 和执行器仍服务关闭开关时的兼容路径、自动整理和历史工具；没有把仍有调用者的代码当作死代码删除。

关闭工作台前需停止并核对活动轮次、独立任务和绑定的活动工作流。关闭开关不会让旧 worker 接手新任务。备份时退出整个应用，完整复制资料目录（数据库、媒体、工作流及 Agent 产物），保留配套程序版本；恢复到独立目录后核对数据库完整性、草稿及媒体。已有临时资料库完整备份恢复及二次启动测试。自动升级前的数据库快照不包含全部媒体，不能替代完整备份。旧二进制若不支持新 schema，必须使用与它匹配的升级前备份；不承诺任意二进制直接降级。
