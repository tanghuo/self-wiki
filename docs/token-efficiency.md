# 整理与图片描述的用量优化

2026-09-09 根据本机用量记录定位，并做第一版优化。沿用用户选择的模型，不自动降低模型档位。

## 发现的浪费

- 当时 97 次整理调用，每次都附了 8 张图片；其中有大量最近导入的候选，尚未确定是否需要查看。整理平均附带约 2.6 万字符的提示词。
- 第一轮图片整理即使已有检索描述、模型没有请求补资料，也会强制用摘要重新检索并再调用一次。97 次调用中有 40 次第二轮、4 次第三轮；这不是说这些后续轮次全部无用。
- 上下文直接序列化展示对象，含时间、图片 URL、文件大小、AI 来源绑定以及重复的语义检索片段。42 份历史快照共 1,085,765 字符；保留正文、引用片段、标签、别名、关系与图片描述的模型输入投影为 519,237 字符，减少 52.2%。此数值仅为资料 JSON 的字符量，不含系统指令、图片或实际 token。
- 每次 CLI 调用使用不同随机工作目录，会改变模型的环境上下文，不利于复用公共前缀。
- 图片描述沿用完整整理输出 schema，要求返回实际不会使用的标签、关系和检索字段。

## 本次行为

1. 优先阅读已有图片描述，以推断依据生成标签和筛选候选。主图片没有描述时直接附原图；其他图片、或已有描述仍需核对细节时，由模型通过 `imageRequests` 请求下一轮补看。
2. `imageRequests` 只能引用已提供的图片候选，整次任务最多 8 张；请求的图片保留在后续上下文中。一次任务内缩略图只下载一次，每次模型调用仍显式附带已读图片，避免把上一独立调用的观察冒充本轮观察。
3. “提示词匹配”和视觉依据仍需要实际附图。仅有描述时不能建立这类视觉结论；描述不是正文，不能伪造逐字引用。
4. 不再为已有描述强制多跑一轮。仅缺少描述时可用首次观察摘要补检索；如果检索没有带来新的可读资料，也没有新图片，就提交上一轮已有依据的结果。仍最多 3 轮，未完成的补图请求不能直接提交。
5. 模型只接收整理需要的资料字段，数据库继续保留完整快照。保留现有正文长度、候选数量和引用校验，不用粗暴截断代替优化。
6. CLI 使用稳定工作目录、独立的临时请求子目录；完成、失败或取消只清理自己的请求文件。图片描述只输出 `summary`。
7. 用量明细增加候选数量及复用描述数量，可与实际附图数、轮次、输入字符一起核对。

## 其他检查结果及边界

- 57 张图片对应 57 个内容哈希，没有发现同图多元素导致的描述重复。60 次描述调用涉及 57 张图片，包含中断后的重试。
- 已有描述在向量重建时会复用；文本索引不需要先调用整理模型。这两条行为保留。
- 聊天记录中缓存输入占比很高，不能把其累计总 token 直接当作全部新增输入。此次没有压缩聊天分支历史或修改用户要求的生图资料。
- 新图片没有描述，或必须核对图片与提示词时，仍有必要的看图成本；本版没有把两类任务合成同一调用，也没有用整理摘要覆盖检索描述。
- 历史用量不改写，不自动重跑已整理内容。无数据库迁移。重启应用加载新 worker；旧版本回退不需要变更数据。

## 验证

子进程及 HTTP 集成验证：缓存描述完成整理只需 1 轮且不附图；从 3 个图片候选中明确请求 1 张时，两轮附图数为 0、1；检索没有增加资料时只发生 1 次模型调用。覆盖视觉依据校验、引用原文、候选保留、并行临时文件隔离、取消及重建复用。

实际模型生成质量和 token 降幅需要后续真实调用验证；这些测试使用固定执行器结果，没有为测量批量重跑用户内容。

本次全量回归 355 项中 353 项直接通过；两项无关的关联操作界面测试在全量运行时超时，单独复测均通过。架构检查与生产构建通过。

## 图片说明操作入口

图片详情页增加“图片说明”，提供“修改说明”和“重新识别”。编辑上限 2000 字，修改与重识别结果沿用现有本地说明存储，不需要数据库迁移或新增开关。重新识别使用当前配置的模型并记录用量，成功后才替换旧说明。

`GET/PATCH /api/elements/:id/description` 读取/修改说明，`POST /api/elements/:id/description/regenerate` 启动重新识别；写请求带读取时的 revision，防止旧页面或迟到识别覆盖新内容。重复识别请求合并到正在执行的操作，同一时间最多一项主动重识别。重识别时暂缓同图的后台索引领取，避免并发识别；保存人工修改取消该图未完成的识别。

新说明使旧向量失效，并按现有搜索配置重新建索引；没有启用向量搜索时也可查看、修改和主动重新识别说明。修改也会使已用旧说明的整理上下文失效。失败保留旧文，未完成的主动识别在退出时取消，不自动重试收费调用；再次打开可手动重试。

验证覆盖版本冲突、向量失效和重建、迟到结果、重复点击、识别失败保留原文、关闭取消、重启保留，以及浏览器内保存失败保留草稿和手机布局。

这次入口更新的全量检查通过：361 项测试、架构检查及生产构建均成功。
