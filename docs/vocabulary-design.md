# 标签与关联名称归一（第一版）

## 目标与现状

同一概念的不同叫法复用主名称，历史内容、筛选、画布与后续 AI 写入一致。[元素仓库](../src/server/data/elementRepository.js)中的 tags 按 normalized_name 去重，element_relations / tag_relations 保存名称与方向；[来源绑定](../src/server/data/organizationProvenanceMigration.js)中的 organization_bindings 关联原始标签和关联记录，支持独立撤销。词表解析和管理分别由[迁移视图](../src/server/data/vocabularyMigration.js)和[词表仓库](../src/server/data/vocabularyRepository.js)实现。

## 决定

- 标签和关联名称分别管理。标签使用现有数字 ID；关联词条使用数字 ID 和完整正反名称对。别名多对一，可串联，禁止循环；关联别名只能连接相同方向类型，按正向名称对齐，不能由别名推断方向。
- 保留原始标签绑定、关联名称、AI 依据和记录 ID；SQL 解析视图统一名称、合并标签成员并折叠完全等价的关联。移除别名只移除映射，未被另行编辑或删除的原始记录重新呈现。
- 后续写入按最新映射检查重复；保留输入的原始叫法。编辑内容时保留仍然被选中的原始标签绑定。显式删除或改名一个折叠关联作用于整组记录，沿用原有人工修改与撤销规则。
- 折叠标签关联改名时保留每个不同的原始目标标签，只消除同一原始目标上的重复记录；解除标签别名后，关联的原有作用范围仍保留。
- 有向关系需要同时指定正反别名和主名称，保持方向；方向未知和旧标题关系不参与名称归并。相似、生成来源与匹配推断不自动互相归并。
- 内置 prompt / prompts → 提示词标签规则。关联名称由用户在设置中按实际含义归并；不按文字相似度自动判断同义，不增加外部模型调用或上下级体系。
- AI 获取主名称和别名；服务端写入统一解析，防止旧叫法再次生成重复绑定。新概念沿用现有建议/自动采纳策略，本版不突然改为所有新词必须审核。

## 数据与接口

迁移 17 新增两个别名表、关联词条表和解析视图；不改写已有绑定。映射增删为短事务，更新资料库 revision，使在途整理上下文过期。设置提供标签/关联两个管理页，列出使用数、例子、现有映射，先预览后应用、可解除。管理接口沿用现有本机及局域网完整应用访问边界；受限仓库实例的标签建议只返回可见内容使用的主标签及别名。

## 验证

覆盖旧库迁移/重启、别名链与循环、同内容多别名去重、标签筛选/画布/标签关联成员、内容编辑后的原名保留、AI 去重与撤销、有向名称对隔离、折叠关联编辑删除、API 权限及浏览器设置操作。构建并运行现有回归检查。

## 评审

采用 sr-design-gate Artifact 路径，并按 sr-review 检查。关键修正：不能重写旧绑定以免损失来源；不能只在 UI 改名，否则筛选与 AI 仍分裂；不能让标签归并扩散进“生成自”等关系语义。实现按上述边界验证，无待用户决定的阻塞。

最终结果：APPROVED（本次名称归一范围）。2026-09-09 验证：`npm run build`、`node --test --test-concurrency=2`（315 项全部通过，无跳过）、`npm run check:arch` 通过。默认高并发全量运行中的浏览器超时已通过降低并发复核。另以 2,500 个标签和内容的内存库检查查询，词表管理读取约 12 ms、标签画布约 18 ms；此数据仅为本机合成样本。

浏览器覆盖桌面预览/应用、已选筛选项随别名更新、别名搜索、有向名称对和手机宽度解除操作。验证使用临时资料库，未对用户正在使用的资料库执行归并；重新启动新版服务时自动应用迁移 17。陌生词仍需自行确认含义后添加别名。
