## 目标与当前事实

用户保存内容后，后台理解内容、查找相关旧内容，自动添加依据充分的标签与关联；不确定结果留作建议。可追溯、可纠正、可恢复中断任务。

当前实现锚点：

- `src/renderer/src/AddContentDialog.jsx` 逐项调用文字创建或图片导入接口，批次仅存在于界面草稿；不能从相邻 ID 或导入时间证明内容之间的来源关系。
- `src/server/application/elementService.js` 统一内容业务入口；图片导入按内容哈希复用。
- `src/server/data/elementRepository.js` 使用短 SQLite 事务；标签更新整组替换，元素列表按更新时间排序，均不适合作为后台增量整理协议。
- `src/server/data/wikiMigrations.js` 当前版本至 6；普通关联无向，标题关联有向，标签关联动态覆盖未来成员。
- `src/cli/commands.js`、`src/cli/main.js` 已有读取、搜索、图片下载、标签与关系写入；CLI 通过 HTTP，不能直接访问数据库。
- `src/server/server.js` 组装服务；`src/main/main.js` 管理桌面生命周期；退出桌面会关闭自带后端。
- 当前工作区已有大量未提交变更，实现时必须基于这些当前文件，保留无关修改。

## 拟采用的边界

Wiki 保存任务、上下文、建议与变更记录，负责最终校验和写入。一个独立 Node worker 领取任务、调用选定的视觉 agent、提交结构化结果。首版单 worker、一次处理一个主元素；候选可以包含其他待整理元素。

按用户决定，模型执行器保留小而明确的兼容接口，首版默认实现本机 Codex CLI。通过配置选择执行器；未来模型 API 或本地视觉模型实现同一接口，任务队列、整理规则和写入协议无需随之修改。

## 执行器接口与配置入口

仓库提供 `config/organization.example.json`，README 提供入口。功能实现后读取实际 `dataDir/organization.json`；随 Wiki 数据目录选择，不能硬编码源码目录的 `data/`。示例只是配置约定，当前应用尚不加载它。

配置示例：

```json
{
  "schemaVersion": 1,
  "enabled": false,
  "applyMode": "suggest",
  "executor": {
    "type": "codex-cli",
    "timeoutMs": 180000,
    "codexCli": {
      "executable": "codex",
      "codexHome": null,
      "model": null
    }
  }
}
```

- `enabled` 控制导入后的自动入队与处理；`applyMode` 为 `suggest` 或 `auto`。`auto` 仍受服务端证据规则约束，不意味着全部模型输出直接写入。
- `executor.type` 首版只接受 `codex-cli`。未来新增类型及其专属配置段；未知类型明确报错，不静默切换或降级到其他模型。
- `executor.timeoutMs` 是一项整理任务的模型执行总时限，覆盖补充上下文的多轮调用；示例初值 180 秒，拟验证范围 1000–1800000 毫秒，与续租周期独立。
- `executor.codexCli.executable` 默认从 PATH 解析 `codex`，允许指定绝对可执行文件路径；不接受带命令参数的 shell 字符串。桌面打包环境可能没有相同 PATH，界面应显示解析后的路径和版本，不能硬编码本次发现的带版本安装目录。
- `codexHome: null` 表示复用 worker 启动环境的 CLI 认证目录；非空时必须是绝对目录。此字段仅定位认证/运行目录，不读取或展示凭据内容，不把登录令牌写进 Wiki 配置。不得自动遍历其他目录寻找凭据。
- `model: null` 表示不传 `--model`，使用受控启动配置下的 CLI 默认模型；非空时传明确模型名。不将全部用户插件、MCP 和 hook 配置自动视为整理器依赖。若需自定义模型供应商配置，应单独支持并验证必要字段。
- 配置文件缺失时使用相同默认值，自动整理关闭；文件存在但 JSON、版本或字段无效时显示可操作的配置错误并停用整理器，Wiki 内容功能仍可使用。拒绝未知字段，避免拼写错误悄悄失效。
- 首版文件配置在启动时读取，离线编辑后重启生效。界面设置通过同一服务校验并原子保存此文件，避免两套状态源；改执行器/模型时停止领取、作废旧租约、停止旧进程，再探测新执行器。探测失败保留配置错误，不能继续用旧执行器静默运行。
- schemaVersion 管理未来配置升级；代码中的静态执行器映射选择实现，不接受从配置导入任意模块路径。首版没有实际实现的类型不出现在可选值中。

接口限定为两个方法，使用项目现有 JavaScript 风格，以 JSDoc/共享校验器定义合同，不为了接口引入 TypeScript：

```text
probe(config) -> { available, version, capabilities, diagnostic }
execute(request, { signal, onEvent }) -> { output, execution }
```

`request` 包含协议版本、任务指令、带 ID/版本的文本上下文、图片附件及输出 schema；`output` 是统一 JSON 结果。`execution` 记录执行器类型/版本、实际模型（未知则留空）、耗时和可获得的用量。`signal` 管理取消，`onEvent` 提供可选进度。进程退出成功、最终输出存在、JSON/schema 校验通过才算执行成功。错误统一为未安装、需登录、能力不支持、额度/限流、超时、取消、输出无效、进程失败；不根据无法证实的错误文字编造精确类别。

worker 拥有检索与循环。模型需要更多资料时返回受限的 `requestContext`（关键词或候选 ID）；worker 校验并通过 Wiki 读取后再调用执行器。最终返回 `organizationProposal`，由 worker 提交给 Wiki。两种输出使用可验证的统一 envelope；请求范围、轮数和输出大小均受限。队列重试、租约 token、数据库路径、写入权限不传给模型，也不塞进执行器接口。

这使 Codex CLI、未来 API 和本地模型都只需支持“文本/图片输入 → 结构化输出 + 取消”，不要求兼容 Codex 的会话 ID、JSONL 事件或原生工具协议。JSONL 解码、参数拼装、临时文件、进程管理留在 Codex 适配器内部。

### Codex CLI 首版实现与核验

2026-09-08 在本次调用环境找到 `codex-cli 0.153.1`。本机 `codex exec --help` 已确认非交互执行、stdin 提示词、`--image`、`--output-schema`、`--json`、`--output-last-message`、`--ephemeral` 与 `--sandbox read-only`；`--ignore-user-config` 可跳过用户主配置且保留 CODEX_HOME 的认证定位。参数与版本须在实际 worker 启动环境再次探测。

使用 Node `spawn(executable, argv, { shell: false, windowsHide: true })` 和 stdin，工作目录为任务专用临时目录；输入图片由 worker 写入，路径与元素 ID 映射明确。只读沙箱，保留管理策略约束。隔离用户插件/MCP/hooks，禁用模型执行 shell 与无关工具的实际效果须核验；不能把只读文件沙箱等同于禁止本机 HTTP 写入。首版由 worker 提供全部上下文或处理结构化资料请求，Codex 无需访问 Wiki HTTP。

CLI adapter 使用 JSONL 获取进度，独立最终输出文件获取结果；工作目录、schema、附件和输出由宿主管理，关闭时终止自己拥有的进程树，确认退出后清理临时目录。未知 JSONL 进度事件可忽略，缺失/无效最终结果不可忽略。CLI 升级后按能力探测和适配器合同测试判断兼容性，不只比较版本号。

本次 `codex login status` 返回 `Not logged in`，仅说明当前调用环境未确认可用认证，不代表用户桌面会话未登录。因此尚未进行真实图片/模型调用，不自动发起登录、不复制凭据；首版 probe 应明确呈现“需要登录”而不是循环重试。

“本机 CLI”指执行器进程在本机；默认 Codex 模型推理仍依赖其配置的服务，不等于离线模型。启动状态展示实际配置的模型及发送位置，不承诺未核实的账户可用性。

依据：[官方非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)说明 exec、结构化结果和复用 CLI 认证；[官方命令参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)说明图片、JSONL 与运行参数；[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)用于核对工具开关。尚未将帮助信息视为端到端功能通过。

第一版自动运行限定为 Wiki 后端运行期间。桌面退出时停止 worker；之后启动继续未完成任务。独立 HTTP 服务模式由服务拥有同样的 worker 生命周期。不是依赖当前聊天持续在线，也不在本次创建定时任务或操作系统服务。

首版整理只新增标签、直接无向关联和内部检索摘要，不改正文、不删内容、不自动合并标签、不创建动态标签关联。生成链与版本链需要有向语义，另行设计，不能借用标题关系表达。

## 整理规则与上下文

1. 读取主元素正文或图片、已有标签、已有关系及其版本；图片先读合适尺寸预览，必要时读取原图。缓存视觉摘要，键包含内容版本、模型及提示词版本；摘要不成为用户新建的文字元素。
2. 先查已有标签与关键词、已有关系，再读取候选正文和图片。新内容可关联任意在用旧元素。候选集固定上限并返回截断信息；未找到候选不能声称全库没有关系。首版不引入向量数据库。
3. 输出结构包含 `summary`、`tagAdds`、`relationAdds`；每个动作附证据类型、证据元素 ID、文字引用或画面观察、理由。模型信心分只作辅助，不作为自动写入条件。
4. 服务端策略决定自动落库或建议。文字明确表达的主题/用途标签、通过样例验证的视觉标签规则可以自动保存；不明身份与来源只给建议。已有人工标签可复用，但不能单独证明生成来源。
5. 自动关系首版仅开放样例确认过的关系名称和证据规则；没有满足规则的关系时允许零新增关联。模型说“很确定”不等于证据。文字引用须校验确实存在，但引用存在也不自动证明模型的推论。
6. 同角色主要通过标签聚合；同批导入、相邻编号、画面相似不能证明参考或生成关系。普通无向关系名称必须适合双方阅读。
7. 用户否定的动作按规范化动作键保存抑制记录，默认持续有效，用户可显式解除；内容更新也不会自动恢复已否定动作。
8. 内容、文件名、图片中的指令属于待分析数据。模型只得到输入资料并返回结构化资料请求或建议，读取与提交由 worker 完成，不让内容决定 shell 命令、文件路径或任意写操作。执行器必须通过工具限制验证才能用于无人值守模式。

## 数据与任务协议

在现有 SQLite 中增加下一版迁移，不额外部署队列服务：

- 元素增加单调 `revision`：正文、标签、回收/恢复、直接关系增删改都会更新受影响元素；关系更新涉及双方。标签关联改变也须更新受影响成员或使依赖它的上下文失效。画布位置不触发整理。
- `organization_jobs`：主元素、内容版本、策略版本、代次、触发来源、状态、尝试次数、可领取时间、租约 token/截止时间、执行器信息和错误。主元素、内容版本、策略版本和代次联合唯一；重复入队返回同一代次，显式重新整理创建新代次。
- `organization_results`：任务、提交幂等键、输入摘要、读取集合与版本、模型/策略版本、摘要、动作、证据和逐项决定。
- `organization_changes`：实际新增的标签绑定/关系及涉及元素写入后的版本、结果 ID、撤销状态。已有相同绑定或关系记为 no-op，不获得撤销所有权。
- `organization_rejections`：主元素与规范化动作键、人工拒绝记录。

上述为职责划分，具体列与索引随实现固定；不得通过 JSON 堆放状态规避唯一性、租约和外键约束。

内容版本与 revision 分开：正文/图片实际内容决定分析版本，元数据变化决定写入校验。人工创建、正文修改可自动入队；人工标签纠正不立即重新入队。agent 写入、关系变化、摘要保存不自动触发新整理，避免循环。重导入同一图片复用已有任务，未整理记录可补入队。

自动整理开启时，内容保存与入队在同一个短事务内完成，覆盖 UI 和 CLI；成功保存必须对应可恢复的任务记录。关闭自动整理时不自动入队，并停止领取自动任务、作废当前自动任务租约、取消执行器调用；已提交结果保留，迟到提交拒绝。待处理自动任务保留，下次开启时重新校验后领取。用户显式选择内容整理使用 manual 来源，允许在自动开关关闭时单次执行。图片文件 I/O 和模型调用保持在事务外。

任务状态：`queued → running → succeeded / failed / cancelled`。`succeeded` 表示建议生成与处理完成，不代表所有建议已自动应用。内容过期的运行取消，并按最新内容重新入队；已回收/删除元素取消，不恢复内容。同一内容的上下文版本冲突将原任务退回 queued 并增加尝试次数，内容变了才创建新内容版本任务。关闭自动整理将自动 running 退回 queued、清除租约。自动暂停不计失败；上下文冲突与执行器错误均受重试上限约束。

领取使用事务与有期限租约，续租必须带当前 token；超时重新入队并作有限退避，超过上限进入 failed，用户可重试。旧 token 禁止提交或续租。相同幂等键与相同请求体的提交返回原结果；同键不同请求体报冲突。网络超时先查结果，不能盲目重跑写入。

上下文接口返回一个短事务取得的内容快照、候选集合和依赖版本。worker 追加读取候选时也记录其版本。提交前核对完整读取集合，不能只检查主元素；关联目标已改变、回收或删除时拒绝过期结果并重新分析。图像字节按对应内容哈希校验。

最终应用由 organizationService 协调、仓库事务实现：校验租约/幂等/版本、服务端规则、成员存在和标签数量上限，再保存结果、以集合增量新增标签与关系、记录实际变化并完成任务。模型调用不持有事务。超限动作保留建议和原因；出现数据库错误整次回滚，不能只保存“任务已完成”。

接受建议也必须重新检查读取版本与拒绝记录，过期建议标记需重新分析。结果保留原始证据版本及独立的当前应用校验版本；同一结果的自动应用或后续接受，在事务内仅将本次自身产生的版本增量推进到应用校验版本，不能吸收并发人工编辑或其他结果的变化。因此自身新增标签不会立即使剩余建议过期，其他写入仍会触发重新分析。用户拒绝自动应用结果会执行条件撤销并记录抑制。

撤销只删除该结果实际新增的绑定/关系；仅当相关元素仍是记录的写入后版本时执行，否则保留当前状态并列为冲突。这个首版规则刻意保守：后续即使是别的标签修改，也可能阻止旧结果撤销。不得整组恢复旧标签覆盖后续编辑。一次结果内部统一按事务结束后的 revision 记录，按该结果整体校验、撤销，避免自己的第一项撤销阻止后续项。

## HTTP、CLI 与模块

拟新增 `src/server/application/organizationService.js`、`src/server/data/organizationRepository.js`、`src/server/http/organizationRoutes.js` 和 `src/shared/domain/organization.js`，分别拥有业务规则、事务与持久化、HTTP 转换、输入约束。

拟新增 `src/agent/main.js`，仅通过 HTTP 访问 Wiki，不导入 server/data；`src/agent/executors/codexCli.js` 实现默认适配器。公共配置校验位于 shared/domain，配置文件读写由 server 的独立配置模块承担，不把节点文件操作放进 shared。接入现有架构检查与打包清单。CLI 继续做命令入口，不承担常驻 worker。

拟提供 `organize enqueue / claim / heartbeat / context / submit / fail / status / result / accept / reject / undo` 命令，对应 `/api/organization/` 路由。提交与复杂操作使用 JSON 文件/stdin；领取返回 jobId、leaseToken、主元素与上下文版本；服务端决定哪些动作自动落库，调用者不能用字段跳过校验。

仅现有本机管理入口开放这些接口，局域网只读入口不开放任务、执行器配置和写操作。worker 视为受信程序；租约 token 防止过期任务写回，不是本机程序的安全隔离或身份认证。模型只返回结构化内容，不能直接接触这些写接口。

## 用户界面与启动

- 设置增加自动整理开关、执行器状态；启用前显示实际使用的执行器和内容发送位置。
- 导入沿用原保存体验，内容保存后展示待整理/整理中/完成/需处理状态。整理失败不改变内容保存成功的事实。
- 详情页显示自动新增项、依据、接受/拒绝建议、撤销本次整理、重新整理入口。状态由服务端读取，不能只存于 React。
- worker 由后端启动并绑定实例与数据目录；退出停止领取、取消模型调用、终止所属子进程后关闭数据库，未完成租约可在下次恢复。Windows 子进程隐藏窗口，不跨实例结束其他 agent。
- 首版单任务限制调用次数、输入图片数量、超时及输出大小；失败可见，避免无限重试。数值根据选定执行器的样例测量确定。

## 实施顺序与验收

1. **配置、执行器与样例验证**：实现配置加载/校验、probe/execute 接口和默认 Codex CLI 适配器；验证实际认证、非交互启动、视觉输入、结构化输出、工具限制和取消。用 #79、#80、#81 及少量旧内容生成可审阅的样例；此步只读。确认首版允许自动落库的标签/关系证据规则。
2. **可靠写入闭环**：一次迁移建立 revision 与任务/结果/变更/拒绝记录，先实现显式入队、领取/租约校验、提交、增量写入、拒绝与条件撤销及 CLI。使用固定结果 fixture 验证，所有结果从一开始即有合法任务外键；不是让模型直接使用现有整组替换标签接口。
3. **持久任务与触发**：完成事务内自动入队、续租、恢复、关闭开关与内容失效处理；接入文字创建/修改、图片导入。默认关闭自动整理，不自动扫描处理全部旧库。
4. **agent 完整运行**：实现上下文、候选检索、图片摘要和选定执行器；串起领取→分析→提交→读取实际结果，并接入后端生命周期。先建议模式验证，再按已确认规则开启自动应用。
5. **界面与集成**：状态、依据、建议处理、撤销/冲突、设置与打包。用新导入实测端到端；通过后支持用户显式选择旧内容补整理。

必须覆盖的有效测试：保存与入队原子性；重复图片与重复提交；租约过期双 worker 竞争；用户分析期间改标签/正文或删目标；正文更新取消旧任务；关系变动导致上下文失效；自身部分应用后仍能接受剩余建议而人工修改使其过期；已存在关系不归 agent 撤销；撤销与后续编辑冲突；拒绝后不复建；任务重启恢复；关闭自动开关拒绝迟到结果且手动整理仍可用；输出无效/服务不可用；自动写入不循环入队；只读局域网不开放新管理接口。

代码完成后运行相关 Node 测试、`npm.cmd run check` 和 `npm.cmd run build`；验证桌面启动退出与打包入口。真实模型效果需样例人工评估，单元测试不能证明语义判断准确。完成定义是：真实新导入自动处理，结果可查可纠正，中断可恢复，且至少一种真实执行器可运行；只有队列/接口不算完成。
