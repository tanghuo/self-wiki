# 工作台执行事件

Grok、Gemini（Antigravity ACP）和 Codex 共用事件存储与时间线。引擎适配器负责转换原生协议，界面不按引擎分支。

- `message.delta`: `text`，可选 `messageId` 和 `phase`。服务缓冲只合并同一消息、同一阶段的文本，遇到活动事件先落盘文本，保持顺序。Codex 保留原生 ID 和阶段；ACP 按连续文本分段，不推测最终回答阶段。
- `tool.updated`: `id`、`title`、`kind`、`status`、可选 ACP `content`。同一轮内按 ID 合并，缺省字段不覆盖旧值。`pending` → `queued`，`in_progress` → `running`。界面按操作数量计数；整轮执行期间保持最近一组活动展开，默认展示最近三项、当前计划及所有未完成操作，支持展开较早记录。工具完成后继续保留最近操作，整轮结束才自动收起；失败不显示成功图标。
- `plan.updated`: `entries` 为最新计划快照，更新原位置。
- `command.completed`: 适配器向服务提交输出，服务保存后发布 `command.output`；可选 `toolCallId` 将输出关联到操作，`commandId` 仍用于分页读取。无关联信息的历史输出独立展示。

已终止轮次中的未完成工具显示“已停止”或“结果待核查”，不推断成功。原始事件保持追加存储，合并只发生在展示层；刷新和历史回放使用相同规则。无 ID、无阶段、无关联信息的历史事件仍可展示。无需数据库迁移。

执行状态行展示当前工具标题和本轮耗时；尚无工具事件时显示“正在等待引擎响应”，工具间隙显示“正在继续处理”。动态标记表示本轮仍在运行，不推测模型思考内容或完成百分比。排队、审批和停止仍显示对应真实状态；减少动态效果设置会关闭动画。

操作默认显示单行摘要，整行可展开查看原始调用及输出，不再嵌套“工具详情”和“命令输出”两层入口。成功仅显示勾选图标，运行、失败和待核查保留状态文字。搜索工具、执行命令等已知动作使用简短中文标签，原始标题完整保留在展开内容中。带 `toolCallId` 的命令输出与对应调用合并；非零退出码优先显示失败，不能被工具的“已完成”状态覆盖。无法关联的历史输出保留独立操作，不按相邻位置猜测归属。完整输出已在预览中时不显示重复读取按钮。

审批、权限、取消和重试仍由现有服务与各引擎原生策略负责。本次统一的是事件约定和交互呈现，不扩展引擎权限或伪造不支持的能力。
