# 工作台交互打磨实施清单

状态：待实施。本文只编排后续改进，不代表功能已经完成。

目标：让长任务中的正文、执行步骤、等待和失败都清楚可读；流式输出期间输入、阅读和切换保持稳定。以当前原工作台为主要改动对象，内嵌 AionUi 继续复用上游消息交互，单列宿主整合事项。

## 现状与实施边界

基于 2026-10-31 工作区源码检查：

- 原工作台已有正文与工具活动分组、工具状态、计划、输出关联、运行中最近操作、轮次结束收起和减少动态效果支持。具体规则见 [执行事件](workbench-execution-events.md)，这些能力应保留。
- `AgentWorkbench.jsx` 的 SSE 回调仍逐条追加事件；每次接收用 `some` 查重，事件变化后直接设置 `scrollTop`。这些是流式更新与滚动打磨的明确入口。
- 原工作台的 Markdown 直接在时间线中渲染；需要先记录渲染情况，再决定缓存和拆分范围。
- AionUi 已在应用内嵌入，已有真实 Grok、官方 ACP 回复验证。审批、断连恢复和全部模型选项仍有验证缺口，见 [实验版说明](aionui-experiment.md)。

本清单优先修改展示与交互。原始事件仍追加保存；审批、重试、取消和计费行为沿用现有服务契约。遇到必须新增后端状态或跨应用接口的条目，先明确契约，再进入实现。

参考 AionUi 的可确认做法：消息更新入队合并、思考更新 50ms 节流、消息项与 Markdown 使用 memo、自动追底按动画帧调度、工具步骤聚合展示。它们是实现参考，不能代替本项目性能测量。

## 执行顺序

| 批次 | 条目 | 完成后可感知的变化 |
| --- | --- | --- |
| 0 | W01 | 有可重复的 A/B 场景与基线 |
| 1 | W02、W03 | 连续输出不频繁抢滚动，输入更稳定 |
| 2 | W04、W05、W06 | 正文、思考、执行步骤清楚，展开状态稳定 |
| 3 | W07、W08、W09 | 等待、失败、停止和再次发送有明确反馈 |
| 4 | W10、W11 | 内嵌入口和宿主切换更连贯，兼容性有实测结论 |
| 5 | W12 | 长会话、窄窗口和键盘操作通过验收 |

建议每次实施一个条目，记录结果后再进入下一项。W04 是否引入增量投影，以 W01、W02 后的测量为依据。

## W01 · 建立固定对比场景（P0）

**改动位置**：`tools/` 下新增可重复回放脚本；复用现有执行事件样例与 UI 测试夹具。

- 准备固定场景：连续正文、正文→工具→正文、工具失败、等待审批、主动停止、断流后恢复、长代码块、长历史回放。
- 性能场景至少含 30 轮历史、1,000 条事件，另以每秒 30 条文本增量持续回放 30 秒；固定浏览器、窗口和缩放比例。
- 记录输入反馈、事件到可见内容的延迟、React 提交次数、长任务和滚动位置；实测记录设备与运行模式。
- 协议回放用于稳定比较；真实 Grok/ACP 用于验证接入链路。两类结果分别记录。

**验收**：同一夹具可重复播放；保存修改前的测量和录屏。后续性能目标属于待验证目标，不能填写为已经达到。

## W02 · 合并流式更新（P0）

**改动位置**：`src/renderer/src/features/agentWorkbench/AgentWorkbench.jsx`；可提取 `useWorkbenchEvents.js`。

- SSE 接收先进入队列，每个动画帧最多提交一次；页面在后台时使用有界定时兜底，避免队列长期不消费。
- 用按会话维护的 seq 集合或索引查重，保持服务给出的事件顺序，不靠“最大 seq”跳过可能迟到的事件。
- 文本、工具、审批和终态按原顺序应用；收到终态时立即刷出待处理内容。
- 切换会话或卸载时取消旧调度；旧会话的异步回调不能写入新会话。原始事件内容与持久化规则保持原样。

**验收**：W01 场景无漏字、重复、错序；后台恢复后内容完整；结束时最后一个增量可见。目标为前台可见更新延迟 P95 ≤100ms，并用测量确认 React 提交次数下降。

## W03 · 稳定自动追底（P0）

**改动位置**：`AgentWorkbench.jsx`；提取 `useWorkbenchAutoScroll.js`，关联 `workbench.css`。

- 独立维护“跟随最新内容”和“正在阅读历史”状态；自动滚动合并到动画帧。
- 用户上滚后停止追底；显示“回到最新”按钮，点击后恢复跟随。避免程序滚动被误判为用户上滚。
- Markdown 高度变化、工具展开、窗口缩放都走同一滚动调度；阅读历史时保留可见消息锚点。
- 会话切换保存并恢复各自阅读位置；首次加载和用户发送新消息的定位行为分别定义并验证。

**验收**：连续输出时上滚阅读 10 秒，视口不会被拉回底部；展开历史步骤不跳走；回到最新后持续跟随；切换会话不会串用滚动状态。

## W04 · 缩小重渲染范围（P1）

**改动位置**：`AgentWorkbench.jsx` 的 Timeline、消息渲染；视需要提取 `WorkbenchMessage.jsx` 与时间线投影模块。

- 消息按会话、轮次和已有消息标识维护稳定 key；不能用会变化的正文或数组位置作为身份。
- 拆出消息项和 Markdown，保持 props 与回调稳定；已完成消息在当前轮增量到达时避免重复解析。
- 先做组件拆分和 memo；若测量仍显示整段事件重算耗时，再加入按 seq 增量更新的时间线投影。
- 增量投影与历史回放使用同一合并规则；对无消息 ID、无阶段的历史事件保持兼容。

**验收**：Profiler 显示追加当前消息时已完成的无关消息不重复渲染；正文与工具穿插顺序正确。W01 场景输入反馈目标 P95 ≤100ms；未达标时保留测量并定位原因。

## W05 · 正文、思考与执行步骤分层（P1）

**改动位置**：Timeline、ExecutionGroup、`workbenchActivity.js`、`workbenchSurface.css`。

- 保持正文→工具组→正文的真实顺序，不能把一轮全部正文提前合并到工具之前。
- 保留现有最近操作与历史展开能力；统一组标题、数量、状态图标和整行点击区域。
- 仅对引擎明确提供的思考事件显示思考折叠块；普通等待继续显示“等待引擎响应”。不从正文猜测思考阶段。
- 思考耗时只在已有可解释时间依据时展示；缺少依据则省略。工具计数按唯一调用 ID，增量更新不重复计数。
- 审批和错误在折叠组外仍有可见提示；终态不能把失败工具改成成功。

**验收**：三种引擎分别验证其实际支持的事件；缺少思考事件也能正常展示。混合回放中顺序、计数、失败状态正确，审批不会被隐藏。

## W06 · 折叠状态与阅读密度（P1）

**改动位置**：ExecutionGroup、CommandOutput、`WorkbenchResults.jsx` 及对应样式。

- 用户主动展开或收起后，新事件不覆盖其选择；自动展开只作用于尚未手动操作的组。
- 轮次结束时按现有规则收起自动展开的过程；用户正在查看的详情保持打开。
- 默认摘要一行；长路径和标题可截断，详情保留原文并支持选择、复制。
- 命令输出保持高度上限和按需读取，保留完整输出入口；避免一条大输出撑满会话。
- 正文、状态、步骤使用统一间距和字体层级；减少动态效果设置下关闭位移和持续旋转动画。

**验收**：持续更新期间手动展开状态不回弹；长标题、长输出不横向撑破布局；复制获得完整原文；键盘可展开和收起。

## W07 · 等待与连接状态可解释（P1）

**改动位置**：轮次状态行、SSE 连接处理、`AionuiExperiment.jsx` 的宿主连接提示。

- 区分正在连接、等待首个响应、工具执行、等待审批、连接中断、已完成和失败；文案只使用已知状态。
- 等待较久时显示已等待时间与查看连接信息入口。没有服务端证据时，不把慢响应直接判为超时失败。
- SSE 断开后提示“连接中断，任务状态待同步”；恢复连接时依据服务端事实更新状态。
- 错误摘要给出下一步动作，详细错误按需展开；连接恢复不自动重发用户任务。

**验收**：模拟慢首包、断流、服务退出和恢复；不永久只显示一个无解释的转圈，不把断流显示为任务成功或自动创建重复轮次。

## W08 · 发送、停止和失败重试反馈（P1）

**改动位置**：输入区、发送与停止处理、现有轮次错误展示。

- 明确发送中反馈，防止快速双击或回车创建重复轮次；提交失败保留草稿和附件。
- 停止请求发出后显示“正在停止”；以服务端终态决定何时结束等待。请求失败保留可操作反馈。
- 失败消息旁给出“编辑后重发”入口，恢复原输入供用户确认；重发使用正常发送路径。
- 保留现有审批规则；原任务仍运行或状态不明时，避免提供会无意创建第二次执行的快捷动作。

**验收**：双击、连续回车、提交失败、停止失败及响应迟到均有可重复用例；编辑重发不会静默重复执行命令或付费操作。

## W09 · 输入区保持稳定（P2）

**改动位置**：输入区、`useWorkbenchTextarea.js`、模型与项目选择器。

- 输出更新不抢输入焦点、不重置光标、不清空未发送草稿。
- 中文输入法组合期间回车不发送；明确 Enter 与 Shift+Enter 行为。
- 多行输入有最大高度，附件和错误提示出现时不遮住发送/停止按钮。
- 运行中模型、项目等选项的可修改范围与现有服务能力一致；禁用项提供简短原因。

**验收**：流式输出中连续输入、选中文字、粘贴多行和添加附件均稳定；中文输入法确认候选词不会误发送。

## W10 · 内嵌 AionUi 的宿主体验（P1）

**改动位置**：`features/aionui/`、`src/main/aionuiView.js`、App 的视图显示与遮挡协调。

- 保留上游消息渲染；宿主只负责连接反馈、布局、切换和必要业务入口。
- 启动提示区分加载与失败，错误后有重新连接入口；不因再次进入页面重复启动服务。
- 验证窗口缩放、显示器 DPI 切换、侧栏变化和应用缩放后的内嵌边界；调度合并重复 bounds 更新。
- 覆盖所有会遮挡内容的宿主弹窗，关闭后恢复视图；切换回原工作台后保留 Aion 会话和草稿。
- 浏览器 iframe 与桌面原生视图分别验证；尚未接入的 Wiki、生图、工作流能力在入口说明中保持准确。

**验收**：反复切换 20 次不新增窗口、不丢草稿；弹窗无遮挡；缩放后无空白缝隙或点击偏移。遇到上游内部问题，记录版本、复现步骤和最小修补位置，再决定是否维护补丁。

## W11 · 内嵌接入兼容性验收（P1）

**改动位置**：`tools/smoke-aionui-embedded.mjs`、实验版文档；确有缺陷时再修改适配层。

- 对 Grok 与官方 ACP 各验证：新建会话、连续两轮、工具执行、批准、拒绝、取消、会话恢复、登录失效、代理不可用和连接恢复。
- 模型切换按各引擎实际暴露的选项验证；未支持项明确记录，不用“正常聊天通过”替代。
- 验证可见回复与目标会话/引擎一致，检查停止后状态收敛；保留耗时和错误信息供排查。
- 真实测试使用专用目录和最小工具任务；需要用户操作的登录或审批步骤单独记录。

**验收**：输出逐项通过、失败或未验证的矩阵；每个失败项附复现步骤。未验证项保留，不能概括成“完全兼容”。

## W12 · 最终视觉与性能回归（P2）

**改动位置**：工作台样式、现有 UI 测试和 W01 回放脚本。

- 验证宽/窄窗口、长路径、长代码块、空会话、历史加载、错误与审批同时出现的布局。
- 键盘可操作发送、停止、折叠、回到最新和审批；状态变化可被辅助技术感知，流式正文避免逐 token 播报。
- 运行 30 轮/1,000 事件固定场景；记录与基线相比的输入延迟、可见更新延迟、长任务及内存趋势。
- 仅当测量证明长历史 DOM 是瓶颈时再引入虚拟列表，并重新验证选择复制、搜索定位、折叠高度和滚动锚点。

**验收**：构建与受影响测试通过；固定回放无事件丢失、无非预期滚动；人工完成中文输入、键盘和缩放检查。性能未达目标时写明实测结果，不能用截图代替性能结论。

## 每项完成时的交付记录

- 修改了哪些文件，以及用户能感知的变化。
- 使用的固定场景、测试结果、实测数值或录屏路径。
- 仍未覆盖的引擎能力和已知限制。
- 出现回归时可独立撤回的改动范围。

优先完成 W01–W03，再用同一段回放比较原工作台和 AionUi。随后以分层、折叠与异常反馈为主线推进，避免同时大改消息模型、布局和协议适配。
