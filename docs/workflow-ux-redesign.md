# 工作流 UI / UX 整理

状态：已按本方案实现。本轮只调整界面，不改变执行契约，也不声明命名的最终输出。

## 目标

用户能清楚完成：搭建流程 → 提供本次输入 → 执行 → 预览与人工审核 → 查看结果。保存到内容库是独立、可选的流程动作。

## 已核对的现状

- `src/renderer/src/features/workflow/WorkflowApp.jsx`：编辑、填写输入与历史运行由本地状态切换。当前填写页只是窄表单，没有流程步骤及预期产物说明；进入已有流程默认打开编辑器。
- `src/renderer/src/features/workflow/WorkflowEditor.jsx`：节点库已有人工检查及保存到内容库；旧 preview 节点不再允许新建。提示词、绑定和节点高级配置占据同一属性栏。
- `src/renderer/src/features/workflow/WorkflowRun.jsx`：运行页以主流程节点列表为主体；审核、产物、失败处理与派生运行散布在节点折叠内容及工具栏中。批次审核已有逐项预览与批量接受能力。
- `src/server/application/workflow/nodes.js`：review 暂停并等待人工决定；library.save 才负责写入内容库。两者不能合并成默认入库行为。
- 当前不能在主流程编辑器里指定命名的最终输出。不能将所有末端节点直接称为用户指定的最终结果。

## 页面和操作

### 1. 工作流列表

每条流程直接提供「运行」「编辑」和最近一次运行入口。频繁使用已有流程时，无需先进入画布。新建、复制、归档保留在列表及流程管理菜单。

### 2. 编辑流程

页面主体保留画布、节点库与选中节点属性。主要动作是保存和运行；导入导出、归档等操作收进管理菜单。保存状态显示在名称附近。

节点库按素材输入、处理、人工审核、保存分组，保留现有节点类型。人工检查的说明明确：预览上游内容，等待接受、修改或拒绝；可作为终点，不自动入库。保存节点说明明确：执行到这里才保存到内容库。

节点名称和字段标签应说明用途。未命名输入只显示类型作为兜底；自动生成名称不能冒充用户对该输入的用途定义。

### 3. 运行工作台

顶部显示具体工作流名称，明确当前是编辑还是运行。准备阶段用可响应的双栏：左侧本次输入和运行按钮，右侧显示步骤概览、哪些步骤需要人工审核、哪些步骤会入库。

运行详情使用独立布局：返回记录、当前运行切换和「再运行一次」在内容区左侧的同一工具栏；本次输入默认折叠，展开后出现在结果上方。待确认内容和产物占主栏，右侧窄栏列出本次执行步骤，点击可展开并定位该步骤。窄屏将步骤导航放到结果之后。暂停和取消收进「运行控制」。

右侧没有结果时显示具体的等待状态。执行开始后输入成为本次快照；新一轮输入与历史运行分开，避免把改动误认为已应用到正在执行的任务。

没有运行时输入时说明使用固定素材。运行和首项试跑应在执行前就标明，避免只在结果页才说明区别。

### 4. 预览和人工审核

需要人工处理的结果优先显示，默认展开图片或文字，以及接受、编辑后接受、拒绝的操作。说明审核影响的是该分支后续执行；存在下游保存节点时明确显示，不把接受描述为保存。

只有一个待确认步骤时保留内容旁的「通过」「跳过」，不显示批量选择或「全部通过」。多个待确认步骤才显示批量入口，选中之后才显示「通过选中的 N 项」。批次运行的批量通过标为「本页全部通过」，状态筛选只用于已有筛选能力的批次列表。等待人工确认时不展示预计完成时间。

批次列表显示原始输入、待审产物、状态和选择操作；保留现有分页及批量接受。普通产物查看、人工审核和错误恢复分别组织，不让用户为看图先打开执行日志。

审核通过后仍可查看这次产物。重新生成沿用现有派生运行，明确会创建新运行，不能将其伪装为原地修改。

### 5. 结果与执行详情

产物和需要处理的事项先于所有节点的执行细节。中间结果可查看；尝试记录、事件、版本派生和定义 JSON 放在明确的执行详情入口。

未配置最终输出时，展示区标为「节点产物」，不能承诺这些就是最终输出。若后续增加最终输出声明，需单独设计定义契约、循环输出、历史快照及兼容迁移，不在本轮用前端启发式冒充实现。

## 实现边界与顺序

1. 整理列表入口、页面导航及编辑器操作层级。
2. 将填写页与执行结果组织为运行工作台；切换时保留草稿、画布选择和撤销状态。
3. 调整运行页的信息优先级，突出预览、审核及可操作失败；保留现有服务端状态与操作接口。
4. 按真实流程做桌面和窄屏视觉检查及浏览器测试，再考虑最终输出声明的独立契约变更。

## 验收

- 已有流程可从列表直接运行，也能明确进入编辑；输入字段不会与配置画布同时显示。
- 输入前可知道要填什么、会执行哪些步骤、是否需要人工审核及是否有入库步骤。
- 运行后无需查找节点日志就能看到产物与待审核内容。
- 图片审核、文字修改、拒绝分支、批量接受和失败恢复均沿用服务端校验。
- 没有 library.save 的流程不会因预览或接受审核而创建内容库元素。
- 已有草稿、历史快照、重试和派生运行不因 UI 调整改变语义。
- 桌面及窄屏可用，正常任务路径不要求填写 JSON。

## 待后续设计

命名的最终输出声明涉及现有定义和历史兼容，需独立完成契约设计。上述 UI 整理可先行，不依赖新增节点类型或最终输出声明。
