# 视频首帧自动关联

2026-09-18；设计门禁：Artifact。范围是补齐现有自动整理器的视频支持。

## 目标与现状

`organizationRepository` 只给文字、图片整理；`agent/main.js` 只读取图片附件。堆叠已支持图片和视频的双向“相似”连通分量。视频卡片缓存的是预览画面，不能作为首帧证据；多帧分析与视觉索引为独立可选功能。

## 决策与边界

- 复用自动整理的配置、队列、租约、审核记录及拒绝/撤销。开启自动整理时，为没有整理记录的既有公开、未删除视频补一次任务；新导入/从私有转公开的视频同样入队。关闭时仅手动任务可运行。失败不会因重启无限重新入队。
- 本机 FFmpeg 解码第一张实际视频帧（不 seek、不使用卡片封面），缩放为有尺寸上限的图片，按不可变存储键缓存。与整段视频分析开关无关，共用 FFmpeg 路径。缺依赖、取消或解码失败明确报错，修复后可从详情重新整理。
- 整理附件允许图片和视频；视频附件明确标注“仅首帧”。首帧仅用于画面相似，不生成整段视频标签、时间标注或来源判断。
- 候选复用已有检索：启用视觉索引时用首帧召回；现有标签、关键词、近期图片/视频继续兜底，首轮首帧描述可用于下一轮语义检索。候选并非穷举全库，检索分数不能直接创建关联。视频候选也必须实际读取首帧比较，不用命中的中间帧代替。
- 图片↔视频、视频↔视频均可保存双向“相似”；服务端必须校验双方附件已提供，涉及视频的相似依据必须是视觉证据。自动模式直接应用，建议模式确认后生效；堆叠沿用现有逻辑，最新素材在前。
- 不改语义索引支持类型，不把视频加入聊天引用或图片生成输入，不启用整段分析或下载视觉模型。

## 一致性与恢复

迁移仅增加视频入队/发布触发器和视频元数据 epoch 时钟；保留已有记录。数据库事务只负责读写快照及任务，抽帧、文件 IO、模型请求全部在事务外。抽帧返回后重新校验视频仍存在且存储键未变，清理过期缓存；应用结果沿用 epoch 与租约检查。缓存跟随彻底删除清理。已有拒绝及人工关联归属保持不变。

## 验收

真实 FFmpeg 验证第一帧而非中间封面、缓存、取消及错误；SQLite 验证入队补齐、幂等/隐私/删除、双附件证据、建议/自动及撤销；隔离模型 fixture 验证 HTTP→首帧→模型→相似关联→混合堆叠，关闭多帧分析仍可工作。UI 开放视频整理入口，构建与架构检查通过。真实模型召回率不由 fixture 证明。

## 设计复核（sr-review）

冻结范围：本文方案及其所引入口。已修正两项边界：不能拿预览封面当首帧；不能对视频直接调用仅支持图文的语义文档接口，须用首帧摘要作查询。APPROVED：接口、生命周期与撤销机制可沿用；实现及真实模型质量尚待分别验证。无用户决策阻塞。

## 实施与验证

- 已接入 schema 37、既有视频补排、独立首帧缓存与读取接口、混合附件及双边证据校验、首帧描述语义查询、视频整理入口和现有堆叠。未改多帧分析的开关语义。
- 118 项后端测试全部通过，包含真实 FFmpeg 首帧/预览区别、失败与取消、完整 worker HTTP 流程、较早图片召回、图片与两段视频混合堆叠、建议/自动/撤销、迁移和旧图文整理回归；5 项整理与视频界面测试通过。构建和架构检查通过。
- 界面回归发现内容刷新期间的空值访问，已修复并复测通过。首次排队不要求重新导入视频，已失败任务可在详情重新整理，重启不会无限重排。
- 本机已通过现有设置接口保存现成的 FFmpeg/ffprobe 路径；真实用户资料未用于模型测试。正在运行的后端需重启以加载新版。模型与视觉编码器使用隔离 fixture 验证链路，真实匹配质量和全库召回率未评测。

实施复核：APPROVED。剩余限制是现有候选窗口与可选视觉索引的覆盖范围；首帧是有限证据，不能代表整片内容。
