# 独立文字与标题关系

用户于 2026-09-07 明确修正：标题也是独立文字，“是标题”是文字与另一元素之间的关系，元素不能继续采用标题加正文模型。

## 确定行为

- 元素仅保存自身文字 `body` 或图片文件及 tags，不再接受或返回 title 属性。界面新增/编辑文字只有一份文字输入，图片只编辑标签。列表预览截取自身文字或文件名，不强制命名。
- 原有普通关联继续无向。新增 `title` 有向关系，source 是标题文字，target 是被命名元素；可在添加关联时选择“选中内容是当前内容的标题”或“当前文字是选中内容的标题”。正文、图片及其他文字都是独立元素，允许同一标题文字关联多个元素，也允许一个元素有多个标题关系。
- 普通关联和标题关系可以并存；同类型同方向去重；自关联禁止，标题来源必须是文字。两边都显示关系及方向。删除/恢复仍保留关系，画布返回方向和类型供展示。
- 第一阶段只增加本次需要的标题关系，不预设 prompt、人物等元素类型。

## 存量迁移

Wiki v4 保留原元素 ID、标签、普通关联 ID、图片原件和画布位置。旧文字只有标题时，将该文字移至 body；同时有标题和正文时，正文留在原元素，新建标题文字并关联。图片默认的文件名标题由 original_name 保留；另行修改的标题迁为关联文字。新拆文字继承原创建/更新时间和回收状态，不推断标签。

重建 elements 去掉 title 列及旧检查，关系表改为 source_id、target_id、kind。迁移在单个事务中完成，临时关闭外键仅用于 SQLite 表重建，提交前检查所有外键，异常回滚并恢复外键开关。启动重复执行不再拆分。
